# 前端迁移分型与执行路由

本文件回答两个问题：

1. 当前任务到底是哪一种前端迁移；
2. 应加载哪些方法、产物和验证，而不是让所有任务执行同一套重流程。

## 一、先区分评估、规划和实施

### 1. 评估

只读回答：是否值得迁、迁哪些、采用什么路径、最大的未知和验证成本是什么。

允许输出：

- 迁移；
- 局部迁移；
- 先补测试 / 先解耦；
- 先做 checkpoint；
- 暂缓；
- 不迁移。

评估阶段不应为了“展示进度”直接批量修改代码。

### 2. 规划

已经接受迁移方向，但还没有足够的目标蓝图、任务边界和裁判。输出 manifest、目标项目画像、蓝图、试迁移和 Gate。

### 3. 实施

范围、目标方向和裁判已经可执行。按小迁移单元修改、验证、切换和清理。

同一请求可以从评估进入规划和实施，但每次跨阶段都要满足退出条件。

## 二、任务规模分型

### Quick

适用于：

- 一个孤立组件；
- 一个低风险配置；
- 已有明确目标范例和测试；
- 不改变 Route、权限、持久状态、SSR、发布路径或全局样式。

Quick 仍需说明：源行为、目标范例、批准差异和验证结果。出现跨页面状态、全局 Token、深链、权限或视觉基线要求时升级为 Slice。

### Slice

适用于一个完整垂直能力，例如：

```text
/orders Route
→ 列表、筛选、分页
→ 请求和缓存
→ Loading / Empty / Error
→ 权限与 deep link
→ analytics
→ 视觉与响应式
```

Slice 是默认迁移单位。它比“一个目录”更稳定，也能独立验证和切换。

### Program

适用于：

- 多个 Route 或页面组；
- 整体框架替换；
- monorepo / workspace 迁移；
- micro-frontend 拆分或合并；
- 新旧实现长期共存；
- 多团队、多 Agent 或多发布批次。

Program 必须有 Workstreams、共享所有权、切换、回滚和旧实现退休条件。

## 三、主模式选择

一个任务可以有多个模式，但必须指定一个主模式。主模式决定首要风险和退出 Gate。

### 模式 A：页面 / 功能切片迁移

**典型请求**

- 把旧项目订单页迁入新项目；
- 把用户中心模块从 Vue 迁到现有 React 应用；
- 把一个后台管理功能并入统一门户。

**优先研究**

- Route、Menu、Tab、deep link、guard；
- 页面状态和交互；
- 请求、缓存、表单、权限；
- 页面布局、响应式和资源；
- 目标项目相似页面。

**常见失败**

- 只迁成功态；
- 漏掉隐藏入口和条件能力；
- 页面能打开但权限、返回路径、scroll restore 或 analytics 不一致；
- 按源组件树一对一重建。

**必要产物**

- manifest；
- 功能生命周期；
- 页面视觉基线；
- 目标实现蓝图；
- 页面级验证报告。

**退出 Gate**

关键 Route、状态、角色、viewport 和交互流程都有源目标证据。

### 模式 B：框架或语言迁移

**典型请求**

- Vue 2 → React；
- AngularJS → Angular / React；
- JavaScript → TypeScript；
- Options API → Composition API；
- class component → function component。

**优先研究**

- 生命周期和 effect 语义；
- computed / memo、watch / effect；
- provide/inject、context、DI；
- slot、children、render prop；
- error boundary；
- async component、Suspense；
- state ownership 和 cleanup；
- TypeScript strictness、runtime validation 和 generated types。

**执行规则**

1. 先运行官方 codemod / schematic；
2. 记录自动转换覆盖范围；
3. 按语义差异而不是语法差异审查；
4. 扫描旧 API、旧依赖和兼容层；
5. 先做代表性复杂组件，不只做静态组件。

**常见失败**

- 把旧生命周期机械映射到 effect；
- 把全局 Store 直接复制；
- 类型只用 `any` 让构建通过；
- 保留旧框架式组件层级。

**退出 Gate**

复杂生命周期、异步状态、卸载清理、错误路径和类型边界都有测试。

### 模式 C：Router / Navigation 迁移

**典型请求**

- React Router 旧版升级；
- Vue Router → React Router；
- SPA Router → Next / Nuxt 文件路由；
- 统一多应用导航。

**优先研究**

- path、params、query、hash；
- nested/index/catch-all route；
- redirect；
- guard、loader、action、error boundary；
- deep link 和 browser history；
- base path、locale、tenant；
- modal route、tab route、scroll restore；
- Menu / breadcrumb / active state。

**常见失败**

- 只迁页面组件，未迁可达性；
- query 默认值或编码变化；
- 404、redirect、back/forward 行为变化；
- SSR 环境直接读取浏览器 API。

**退出 Gate**

Route inventory 可机读，关键 deep link、redirect、guard 和 history flow 通过 E2E。

### 模式 D：State / Data Fetching / Form 迁移

**典型请求**

- Vuex / Redux → Pinia / Zustand；
- 自研请求层 → React Query / SWR；
- Redux Form → React Hook Form；
- 把服务端状态从全局 Store 中拆出。

**优先研究**

- server、URL、local、shared client state 的边界；
- cache key、stale、retry、cancellation；
- optimistic update 和 rollback；
- persistence、schema version 和 migration；
- form validation 时机、dirty、touched、submit；
- error mapping、toast、field error；
- websocket / polling / background refresh。

**常见失败**

- 所有状态继续进入一个全局 Store；
- cache key 或 invalidation 不一致；
- optimistic failure 无回滚；
- localStorage 结构变化导致已安装用户丢状态；
- 表单只迁 happy path。

**退出 Gate**

数据状态机、缓存、失败、并发、持久化和表单状态都有裁判。

### 模式 E：Component Library / Design System / Styling 迁移

**典型请求**

- MUI → Ant Design / BUI / shadcn；
- Less → CSS Modules / Tailwind；
- 旧 Design System → 新 Token；
- 全局 CSS → scoped styling。

**优先研究**

- 控件可观察语义而不是组件名称；
- density、size、spacing、typography、icon；
- hover、focus、disabled、loading、validation；
- overlay、portal、z-index、scroll lock；
- responsive props、theme、dark mode；
- CSS reset、specificity、global leakage；
- SSR style extraction 和 hydration。

**常见失败**

- 认为同名 `Button` 视觉和交互等价；
- 用大量局部覆盖对抗新组件库；
- Token 映射不完整；
- portal、focus trap、日期/时区行为变化；
- 为通过截图无限调高阈值。

**退出 Gate**

关键组件状态矩阵、页面级视觉、键盘和 overlay 行为通过；批准差异有记录。

### 模式 F：Bundler / Runtime / Workspace 迁移

**典型请求**

- CRA / Webpack → Vite；
- Webpack → Rspack；
- npm → pnpm workspace；
- 单包 → Nx / Turborepo；
- CJS → ESM。

**优先研究**

- entry、HTML、public path、asset URL；
- env variable 前缀与注入时机；
- alias、TS paths、CSS preprocessors；
- worker、WASM、SVG、raw import；
- code splitting、chunk naming、preload；
- proxy、dev server、HMR；
- test runner 与 build transform 差异；
- CI、Docker、部署、source map；
- workspace hoist、peer dependency 和 package boundary。

**常见失败**

- 只让 dev server 启动；
- 忽略生产 base path 和静态资源；
- 环境变量在客户端泄漏；
- test 和 build 使用不同 transform；
- lockfile 和 workspace 边界被意外重写。

**退出 Gate**

开发、测试、生产构建、预览、CI 和部署产物均验证；关键资源和环境配置无残留。

### 模式 G：SPA ↔ SSR / SSG / RSC 迁移

**典型请求**

- React SPA → Next.js；
- Vue SPA → Nuxt；
- CSR 页面改为 SSR / SSG；
- Next Pages Router → App Router。

**优先研究**

- server/client boundary；
- data fetching、cache、revalidation；
- auth/session 和 cookie；
- hydration、streaming、Suspense；
- browser-only API；
- metadata、SEO、canonical、locale；
- serialization；
- edge/runtime 限制；
- loading、error、not-found boundary。

**常见失败**

- 通过 `useEffect` 重建纯客户端旧结构；
- server component 传递过量数据；
- hydration mismatch 被静默 suppress；
- auth 和 cache 在请求间串数据；
- metadata、404 和 deep link 遗漏。

**退出 Gate**

服务端渲染结果、hydration、cache、权限、metadata 和客户端交互均有证据。

### 模式 H：Micro-frontend 迁移

**典型请求**

- 从单体拆出独立前端；
- 多微前端合并；
- Module Federation / qiankun / single-spa 宿主迁移。

**优先研究**

- ownership、Route 和 deployment boundary；
- shared dependency、singleton、version skew；
- auth、session、locale、theme、analytics；
- event contract 和 navigation；
- CSS isolation、portal、z-index；
- failure isolation、loading、timeout；
- local dev、CI、preview 和 rollback。

**常见失败**

- 按目录而非独立业务能力拆分；
- 共享状态形成隐式耦合；
- React/Vue 等 runtime 重复加载；
- 宿主和子应用路由互相争夺；
- 临时桥接层没有退休日期。

**退出 Gate**

宿主边界、共享契约、独立发布、失败隔离和版本回滚已验证。

### 模式 I：测试体系迁移

**典型请求**

- Jest → Vitest；
- Enzyme → Testing Library；
- Cypress → Playwright；
- 新增 Storybook visual regression。

**优先研究**

- 测试意图和公共行为；
- module mocking、fake timers、jsdom/browser 差异；
- fixture、auth、network interception；
- flaky retry 和并发；
- screenshot environment；
- coverage 的有效性而不是数字保持。

**常见失败**

- 为迁移测试而改产品行为；
- 保留大量实现细节断言；
- snapshot 全量更新而不审查；
- E2E 只覆盖页面打开；
- 测试迁完但失去旧裁判能力。

**退出 Gate**

新测试能够发现故意注入的关键回归，并覆盖迁移 manifest 中的验收场景。

## 四、模式组合示例

### Vue 2 订单页迁入 Next.js App Router

- 主模式：页面 / 功能切片；
- 次模式：框架、Router、State/Data、SSR、Styling；
- 先做：Route 和状态盘点、视觉基线、目标 Next.js 范例；
- 代表性试迁移：带筛选、分页、权限、错误态和移动端的订单列表；
- 不应先做：批量把所有 `.vue` 转成 `.tsx`。

### CRA → Vite

- 主模式：Bundler / Runtime；
- 次模式：Test；
- 先做：entry、env、asset、alias、proxy、SVG/worker、CI 和部署盘点；
- 代表性试迁移：生产 build + preview + 一个依赖特殊 loader 的页面；
- 不应只验证：`npm run dev` 能启动。

### MUI → 新 Design System

- 主模式：Component Library / Styling；
- 次模式：页面切片、Accessibility；
- 先做：组件状态矩阵、Token 映射、overlay/focus、截图环境；
- 代表性试迁移：包含 Form、Dialog、Table 和响应式的页面；
- 不应先做：全仓库 import 替换。
