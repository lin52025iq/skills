# 迁移边界与目标架构

## 一、目标

确定“哪些能力真正需要进入目标项目”，以及“这些能力应该怎样以目标原生方式融入目标项目现有架构”。

迁移边界的单位是业务能力、数据所有权和契约，不是目录、类或表。

## 二、能力分类

对源能力使用以下分类：

### 迁移

目标项目应拥有该能力，需要建立目标实现。

### 复用

目标项目已经存在等价能力，应使用现有实现，不重复建设。

### 适配

能力仍由原系统、第三方或其他服务提供，目标项目只通过适配层访问。

### 替换

业务能力保留，但技术实现使用目标技术栈或目标项目已有方式替换。

### 保留

当前迁移阶段仍留在源系统，可能通过远程调用继续使用。

### 淘汰

经证据确认已经不再需要。

### 待确认

当前证据不足，不提前决定。

## 三、识别隐藏边界

特别检查：

- 源模块是否直接写其他业务域的数据；
- 其他模块是否绕过公开接口调用内部实现；
- 是否存在共享数据库；
- 是否通过缓存共享隐式状态；
- 是否存在多个生产者写同一业务数据；
- 是否存在多个消费者改变同一状态；
- 定时任务是否补充主流程行为；
- Feature Flag 是否让不同用户走不同实现；
- 是否存在仍生效的历史兼容逻辑。

## 四、目标已有能力是否真的等价

不要只因为名称相同就复用。至少比较：

- 输入与输出；
- 错误语义；
- 状态变化；
- 数据一致性；
- 权限；
- 幂等；
- 时序；
- 外部副作用；
- 性能和容量；
- 生命周期。

只能覆盖部分行为时标记为“适配”或“部分复用”，并明确缺口。

## 五、先理解目标项目，再设计目标代码

优先研究目标项目中维护良好、近期活跃、测试充分的相似模块：

- 一个相似功能如何组织；
- 入口层如何定义；
- 业务规则放在哪里；
- 数据访问如何抽象；
- 错误如何表达和映射；
- 事务如何创建和传播；
- 消息如何发布和消费；
- 配置如何注入；
- 测试如何组织；
- 日志和指标如何记录；
- 权限在哪里处理。

目标项目已有稳定惯例通常比源项目结构更值得继承。

## 六、目标态与迁移态必须分开

### 目标态

迁移结束并清理临时设施后，希望长期保留的架构。

### 迁移态

为了新旧并存而暂时存在的结构，例如：

- proxy；
- Feature Flag；
- adapter；
- ACL；
- 双读 / 双写；
- 同步任务；
- 兼容 DTO；
- 临时路由。

每个迁移态设施必须记录：为什么需要、风险、何时删除、由什么证据证明可以删除。

不要让临时架构因为“以后再清理”永久化。

## 七、选择渐进迁移模式

### Strangler Fig

适合外围调用可以路由、新旧系统需要长期并行、希望逐步切换能力或流量的场景。

### Branch by Abstraction

适合内部深层组件被大量调用、无法从外围直接切流时。先建立稳定抽象，让旧、新实现并存，再逐步切换调用者。

### Anti-Corruption Layer

适合源系统与目标系统的数据模型、错误模型或协议语义差异大。ACL 负责翻译边界，不应成为新的业务逻辑堆积层。

### 直接替换

适合低风险、独立、验证充分、容易回退的小能力。

模式不是目标。选择能降低当前迁移风险、且不会制造长期无价值复杂度的最简单方案。

## 八、建立源概念到目标概念映射

映射描述语义，不描述文件名。

示例：

```text
源：框架事务注解
目标：目标项目应用服务边界内的事务执行器
语义：同一用例的关键数据库写入必须原子提交
```

```text
源：本地用户 DAO
目标：目标项目已有用户服务客户端
语义：订单模块不再拥有用户主数据，只消费用户查询能力
```

## 九、源设计问题必须有明确去向

对发现的设计问题，不要默认复制，也不要无限扩展重构。

分类：

- 必须改；
- 应该改；
- 后续改。

详见 `09-设计现代化与代码质量.md`。

目标架构映射中要说明：

```text
源设计问题
→ 目标设计决策
→ 为什么更适合目标项目
→ 是否改变可观察行为
→ 验证方式
```

## 十、避免迁移式重复建设

典型重复：

- 两套用户模型；
- 两套权限判断；
- 两套日志规范；
- 两套错误码体系；
- 两套消息客户端；
- 两套数据库事务封装；
- 两套配置加载方式。

迁移目标应该降低长期系统复杂度，而不是把两个项目的历史同时保留。

## 十一、边界阶段完成标准

每个关键能力都能回答：

- 它是否进入目标项目；
- 如果不进入，未来由谁提供；
- 目标项目通过什么契约访问；
- 数据所有权属于谁；
- 是否存在临时并行方案；
- 目标态是什么；
- 迁移态是什么；
- 临时设施何时清理；
- 源设计问题如何处置；
- 如何验证迁移后的等价性或批准差异。
