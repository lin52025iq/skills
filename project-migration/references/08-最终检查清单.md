# 迁移最终检查清单

此清单用于迁移结束前的独立总体验收。根据项目实际删减不适用项，但不能默认为“不需要检查”。

## 一、范围与能力

- [ ] 迁移范围与当前实现一致。
- [ ] 每个关键源能力都有明确目标去向。
- [ ] 没有关键能力处于未分析或待确认状态。
- [ ] 决定不迁移或淘汰的能力已有依据。
- [ ] 目标项目没有明显重复建设已有能力。

## 二、业务规则

- [ ] 关键业务规则已经记录。
- [ ] 每条高优先级规则有目标实现。
- [ ] 每条高优先级规则有验证证据。
- [ ] 特殊客户、地区、版本和特性开关逻辑已检查。
- [ ] 没有未经批准的业务规则变化。

## 三、接口与事件

- [ ] 请求字段兼容要求满足。
- [ ] 响应字段兼容要求满足。
- [ ] 错误码和状态码满足要求。
- [ ] 消息或事件 Schema 满足兼容要求。
- [ ] 幂等键和业务键语义保持正确。
- [ ] 版本策略明确。

## 四、数据

- [ ] 数据所有权明确。
- [ ] Schema 变化已验证。
- [ ] 唯一约束、非空约束、默认值等规则已保留或明确变更。
- [ ] 历史数据迁移已验证。
- [ ] 双写或同步策略有停止条件。
- [ ] 回滚后的数据处理方式明确。
- [ ] 没有不可解释的数据差异。

## 五、事务与失败

- [ ] 事务边界符合业务要求。
- [ ] 重复请求处理正确。
- [ ] 重复消息处理正确。
- [ ] 超时行为正确。
- [ ] 重试行为正确。
- [ ] 部分成功有补偿或明确策略。
- [ ] 并发冲突处理正确。
- [ ] 外部依赖失败路径已验证。

## 六、安全与权限

- [ ] 身份认证未丢失。
- [ ] 权限检查未丢失。
- [ ] 审计要求满足。
- [ ] 敏感数据处理正确。
- [ ] 新技术栈没有绕过原安全中间件或框架行为。

## 七、技术栈差异

- [ ] 空值语义已检查。
- [ ] 数值与金额精度已检查。
- [ ] 时间与时区已检查。
- [ ] 序列化已检查。
- [ ] 错误模型已检查。
- [ ] 并发模型已检查。
- [ ] ORM 行为已检查。
- [ ] 消息投递语义已检查。
- [ ] 缓存语义已检查。

## 八、验证

- [ ] 构建或基础运行通过。
- [ ] 静态检查通过或差异已接受。
- [ ] 关键单元测试通过。
- [ ] 关键集成测试通过。
- [ ] 契约验证通过。
- [ ] 高风险能力已有行为对照或等价验证。
- [ ] 关键端到端流程通过。
- [ ] 数据一致性通过。
- [ ] 仍存在的差异已有明确解释。

## 九、运行与观测

- [ ] 关键日志存在。
- [ ] 关键业务指标存在。
- [ ] 错误和延迟指标存在。
- [ ] 消息积压可观测。
- [ ] 关键告警已配置或确认不需要。
- [ ] 性能和容量满足既定要求。

## 十、切换与回滚

- [ ] 切换方案明确。
- [ ] 回滚触发条件明确。
- [ ] 回滚操作明确。
- [ ] 数据回滚或补偿方式明确。
- [ ] 新旧并行时的数据权威明确。
- [ ] 灰度扩大条件明确。
- [ ] 清理旧实现的条件明确。

## 十一、完成声明

只有阻断级项目全部通过或由用户明确接受后，才允许声明迁移完成。

完成声明应同时列出：

- 已验证的核心能力；
- 主要验证证据；
- 已接受的差异；
- 仍保留的非阻断事项；
- 切换状态；
- 是否已允许清理旧实现。
