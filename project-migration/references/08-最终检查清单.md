# 迁移最终检查清单

用于迁移结束前独立总体验收。根据项目实际删减不适用项，但不能默认为“不需要检查”。

## 一、可行性与范围

- [ ] 迁移仍然解决最初定义的问题。
- [ ] 当前范围与实际实现一致。
- [ ] 没有因为实施惯性继续迁移已经不值得迁的能力。
- [ ] 每个关键源能力都有明确终态。
- [ ] 不迁移、保留或淘汰的能力有依据。

## 二、源系统理解

- [ ] 关键入口和调用者已覆盖。
- [ ] 核心业务流程和状态变化已覆盖。
- [ ] 数据、事件、缓存、任务和外部副作用已覆盖。
- [ ] 失败、重试、并发、幂等、事务和补偿已检查。
- [ ] 关键推断和未知项没有被伪装成事实。

## 三、业务规则

- [ ] 关键业务规则已经记录。
- [ ] 每条高优先级规则有目标实现。
- [ ] 每条高优先级规则有验证证据。
- [ ] 特殊客户、地区、版本和 Feature Flag 已检查。
- [ ] 没有未经批准的业务行为变化。

## 四、目标架构与设计质量

- [ ] 目标实现遵循目标项目已有稳定惯例。
- [ ] 没有机械复制源目录、类和层次。
- [ ] 本次“必须改”的源设计问题全部关闭。
- [ ] “应该改 / 后续改”都有明确决策。
- [ ] 没有重复建设目标项目已有能力。
- [ ] 模块职责和依赖方向清晰。
- [ ] 核心业务没有不必要依赖具体框架或基础设施。
- [ ] 事务、副作用和错误边界清晰。
- [ ] 没有为了最佳实践增加无价值抽象。
- [ ] 临时迁移架构有明确清理条件。

## 五、技术栈迁移规则

- [ ] 空值语义已检查。
- [ ] 数值与金额精度已检查。
- [ ] 时间与时区已检查。
- [ ] 序列化已检查。
- [ ] 错误模型已检查。
- [ ] 并发模型已检查。
- [ ] ORM 行为已检查。
- [ ] 消息投递语义已检查。
- [ ] 缓存语义已检查。
- [ ] 源框架隐式行为已检查。
- [ ] 目标语言/框架惯例已明确。

## 六、验证裁判与试迁移

- [ ] 存在能评价关键旧、新行为的裁判。
- [ ] 裁判已在旧实现上验证。
- [ ] 条件允许时已验证裁判能识别故意错误。
- [ ] 高风险迁移已经用难样本压力测试规则或目标设计。
- [ ] 试迁移暴露的问题已经回写规则、架构或计划。

## 七、接口与事件

- [ ] 请求和响应字段满足兼容要求。
- [ ] 状态码、错误码满足要求。
- [ ] 消息或事件 Schema 满足兼容要求。
- [ ] 幂等键和业务键语义正确。
- [ ] 版本策略明确。

## 八、数据

- [ ] 数据所有权明确。
- [ ] Schema 变化已验证。
- [ ] 唯一、非空、默认值等规则已保留或明确变更。
- [ ] 历史数据迁移已验证。
- [ ] 双写或同步策略有停止条件。
- [ ] 回滚后的数据处理明确。
- [ ] 没有不可解释数据差异。

## 九、事务与失败

- [ ] 事务边界符合业务要求。
- [ ] 重复请求和重复消息处理正确。
- [ ] 超时和重试正确。
- [ ] 部分成功有补偿或明确策略。
- [ ] 并发冲突处理正确。
- [ ] 外部依赖失败路径已验证。

## 十、安全与权限

- [ ] 身份认证未丢失。
- [ ] 权限检查未丢失。
- [ ] 审计要求满足。
- [ ] 敏感数据处理正确。
- [ ] 新技术栈没有绕过原安全能力。

## 十一、验证结果

- [ ] 构建或基础运行通过。
- [ ] 静态检查通过或差异已接受。
- [ ] 关键单元、集成、契约测试通过。
- [ ] 高风险能力有行为对照或等价验证。
- [ ] 关键端到端流程通过。
- [ ] 数据一致性通过。
- [ ] 未关闭差异都有明确解释。
- [ ] 没有通过削弱测试掩盖迁移问题。

## 十二、重复失败与规则稳定性

- [ ] 没有持续重复但仍只逐个修实例的同类失败。
- [ ] 规则变化后受影响的已完成任务已经重新检查。
- [ ] 批量迁移规则已达到当前范围可接受的稳定性。

## 十三、运行与观测

- [ ] 关键日志存在。
- [ ] 关键业务指标存在。
- [ ] 错误和延迟指标存在。
- [ ] 消息积压可观测。
- [ ] 关键告警已配置或确认不需要。
- [ ] 性能和容量满足既定要求。

## 十四、切换与回滚

- [ ] 切换方案明确。
- [ ] 回滚触发条件明确。
- [ ] 回滚操作明确。
- [ ] 数据回滚或补偿明确。
- [ ] 新旧并行时的数据权威明确。
- [ ] 灰度扩大条件明确。
- [ ] 临时 proxy / ACL / adapter / 同步逻辑清理条件明确。

## 十五、完成声明

只有阻断级项目全部通过或由用户明确接受后，才允许声明迁移完成。

完成声明至少列出：

- 已验证核心能力；
- 已验证高优先级业务规则；
- 已完成的必须改设计项；
- 主要验证证据；
- 已批准行为差异；
- 仍保留非阻断事项；
- 切换状态；
- 是否允许清理旧实现和临时迁移设施。
