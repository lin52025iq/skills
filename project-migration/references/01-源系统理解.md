# 源系统理解方法

## 目标

建立一个足以支撑迁移决策的源系统行为模型。重点不是生成代码目录说明，而是理解业务能力、业务规则、数据、契约、副作用和失败语义。

## 一、从入口出发，不从目录出发

优先找到真实入口：

- HTTP、RPC、GraphQL 或其他接口；
- 前端路由和用户动作；
- 消息消费者；
- 定时任务；
- 事件监听器；
- 命令行入口；
- 后台管理动作；
- 对外暴露的库接口。

对每个入口建立最小调用链：

```text
入口
→ 参数或消息解析
→ 权限与前置校验
→ 业务编排
→ 领域规则
→ 数据读写
→ 外部调用
→ 消息或其他副作用
→ 返回或最终状态
```

然后再从调用链向外扩散，寻找间接依赖。

## 二、五轮阅读

### 第一轮：结构视角

需要回答：

- 模块物理位置在哪里；
- 主要包、目录、组件是什么；
- 哪些是入口；
- 哪些是领域核心；
- 哪些是基础设施；
- 哪些是共享能力。

本轮只建立地图，不急着下业务结论。

### 第二轮：业务视角

对每个主要用例回答：

- 谁触发；
- 输入是什么；
- 前置条件是什么；
- 系统如何决策；
- 状态如何变化；
- 成功意味着什么；
- 用户或上游能观察到什么结果。

优先从测试用例名称、断言和领域代码中提取业务规则。

### 第三轮：依赖与副作用视角

检查：

- 数据库表和字段；
- 缓存键；
- 搜索索引；
- 对象存储；
- 外部 API；
- SDK；
- 消息主题或队列；
- 发送邮件、短信、通知；
- 审计记录；
- 文件输出；
- 任务调度；
- 其他服务写入。

不要把“函数返回值”误认为完整行为。真实业务效果常常在副作用中。

### 第四轮：失败与边界视角

对每条关键路径检查：

- 参数非法；
- 数据不存在；
- 数据重复；
- 权限不足；
- 外部服务失败；
- 网络超时；
- 部分步骤成功；
- 数据库提交失败；
- 消息发送失败；
- 重复消息；
- 并发请求；
- 任务重复执行；
- 重试后再次成功；
- 补偿失败。

特别关注 catch、recover、defer、finally、重试装饰器、事务、锁、唯一约束和状态判断。

### 第五轮：反证视角

主动搜索能否找到与当前理解冲突的代码。

推荐搜索：

- 同一接口的多个实现；
- 同一状态的所有判断；
- 同一表的其他写入者；
- 同一事件的其他生产者或消费者；
- 同一配置项或特性开关的使用位置；
- 已弃用但仍可触达的代码；
- 特殊客户、租户、区域、版本逻辑；
- 测试中的边界案例；
- 历史提交中与关键规则有关的修复。

如果反证改变原结论，应更新迁移文档，而不是只在对话中说明。

## 三、测试是业务证据，不只是质量工具

分析测试时重点提取：

- 测试名称描述的业务条件；
- arrange 部分构造了哪些状态；
- act 触发了什么操作；
- assert 真正关心什么；
- 是否检查数据库、副作用、事件或外部调用；
- 是否存在参数化边界；
- 是否存在历史 bug 的回归测试。

如果生产代码和测试表达不一致：

1. 确认测试是否仍执行；
2. 确认测试是否覆盖当前实现；
3. 查看版本历史或相关代码；
4. 把冲突记为未知项或风险，不要擅自选择其中一个作为真相。

## 四、数据库是隐藏业务规则的重要来源

必须检查：

- 主键；
- 唯一约束；
- 非空约束；
- 外键；
- 默认值；
- 检查约束；
- 索引；
- 触发器；
- 存储过程；
- 数据库迁移历史。

例如代码中没有显式幂等逻辑，但数据库存在业务键唯一约束，这仍然可能是系统幂等保障的一部分。

## 五、配置与运行环境也是行为的一部分

检查：

- 超时时间；
- 重试次数；
- 批大小；
- 并发数；
- 队列配置；
- 定时表达式；
- 特性开关；
- 环境变量；
- 限流；
- 熔断；
- 日志级别；
- 安全策略。

不要只看默认配置。不同环境的配置差异可能代表重要业务要求。

## 六、如何记录证据

每个高价值结论写清：

- 结论；
- 类型：证据、推断或未知；
- 证据位置；
- 业务意义；
- 对迁移的要求；
- 置信度；
- 若未确认，下一步如何确认。

证据位置应尽量包含：

- 文件路径；
- 符号名；
- 测试名；
- 表或约束名；
- 配置项名。

不要依赖容易失效的绝对行号作为唯一定位方式。

## 七、完成源系统理解前的自检

至少能回答：

1. 这个能力为谁服务？
2. 有哪些入口？
3. 核心业务流程是什么？
4. 哪些规则决定结果？
5. 写哪些数据？
6. 读哪些数据？
7. 调用哪些外部系统？
8. 产生哪些消息或副作用？
9. 失败和部分成功如何处理？
10. 哪些动作需要幂等？
11. 哪些操作需要事务或并发控制？
12. 权限在哪里判断？
13. 哪些行为由配置控制？
14. 哪些业务规则只有测试或数据库约束体现？
15. 当前还有哪些高风险未知项？

如果这些问题中与迁移范围直接相关的部分仍大量未知，继续理解，不要进入批量实现。
