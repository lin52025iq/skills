# 02 功能语义与业务规则

## 目标

把源代码转换为与技术栈无关的功能语义，恢复用户真正依赖的能力、规则、交互语义和不可破坏条件，同时避免把 Agent 推测写成源系统事实。

## 功能模型

每个关键功能至少回答：

```text
角色
入口
前置条件
动作
业务规则
数据
副作用
结果
失败
生命周期
证据
来源类型
```

不要把文件、Hook、Store 当作功能；它们只是实现证据。

## 来源与事实边界

功能 / 子项来源使用：

```text
源系统证据 / 用户明确新增 / 目标产品要求
目标项目强制约束 / 推断候选 / 未知
```

**源系统事实、目标需求、设计建议必须分开。**

例如：

```text
发现事实：源系统没有批量导出
目标需求：用户没有要求新增批量导出
设计建议：目标系统未来可考虑增加导出
```

设计建议不能自动升级为范围内必需功能。

## 逻辑分类

阅读旧代码时，将重要逻辑归类为：

- **领域规则**：核心业务规则；
- **用户可观察行为**：用户能直接感知的行为；
- **交互语义**：触发、中间状态、反馈、恢复和收尾；
- **集成契约**：API、事件、SDK 等契约；
- **自动行为 / 副作用**：轮询、缓存失效、事件、Storage、刷新、跳转；
- **框架机制**：由框架要求产生；
- **基础设施机制**：构建、缓存、环境等机制；
- **历史兼容 / 临时修复**：旧约束下的折中；
- **Bug 兼容行为**：看似 Bug 但可能被依赖；
- **技术债**：可识别但不应默认复制；
- **无效代码**：有证据证明不再使用；
- **未知**：证据不足。

**不要默认复制历史兼容和技术债，也不要在缺少证据时删除可能被依赖的行为。**

## 交互语义模型

关键交互不能只记录“有按钮 / 调 API”，至少描述：

```text
前置条件
触发方式
即时反馈
中间状态
数据操作
成功结果
失败结果
副作用
交互收尾
```

适用时继续记录：

- 显示 / 隐藏 / Disabled 条件；
- Page / Modal / Drawer / Popover / Inline 形态；
- Loading / Optimistic Update；
- 重复点击、并发、取消、debounce / throttle；
- 表单草稿和输入是否保留；
- 成功后的 Toast、关闭、刷新、跳转；
- 失败后的错误定位、重试、输入保留和状态回滚；
- URL、Deep Link、Back / Forward；
- Focus、Tab、Enter、Esc、快捷键；
- Scroll Lock、滚动位置恢复。

例如：

```text
交互：发起退款
前置条件：已付款 + 有退款权限
触发：点击退款按钮
立即反馈：打开退款 Drawer
提交中：按钮禁用 + Loading，禁止重复提交
成功：关闭 Drawer + Toast + 刷新订单/退款历史/Timeline
409：不关闭 Drawer，保留输入，显示冲突恢复提示
```

## 交互决策

当目标交互与源项目不完全一致时使用：

```text
保持交互 / 目标适配 / 按新方案重构
合并交互 / 拆分交互 / 移除交互
新增交互 / 复用目标交互 / 未知
```

用户明确的新交互方案优先于源系统旧交互。例如源系统点击行跳详情页、用户要求改成右侧 Drawer，应记录“按新方案重构”，验证目标 Drawer 方案，而不是把目标修回页面跳转。

## 交互不变量

实现形态可以变化，但仍可能存在必须保留的交互不变量，例如：

- 提交中禁止重复提交；
- 409 后必须保留用户输入；
- 未保存离开必须确认；
- 关闭弹层后焦点返回触发元素；
- 返回列表后保留筛选与分页；
- 某操作必须有二次确认。

这些应进入源行为或 `08-页面结构与交互对齐清单.md` 并参与验证。

## Invariant

重点提取无论技术栈如何变化都必须成立的条件，例如：

- 权限不足不能执行审批；
- 某状态不能跳过中间状态；
- 金额以服务端最终计算结果为准；
- 一个实体只能存在一个有效进行中流程。

Invariant 应优先进入测试或运行验证。

## 生命周期

源能力使用中文标记：

```text
现役 / 条件启用 / 已废弃 / 已移除 / 未知
```

代码存在不是“现役”的充分条件。

## 数据契约与副作用

记录输入、输出、枚举、分页、时间、金额、错误码、权限字段和副作用。特别检查：

- Mutation 后哪些 Query / Cache 失效；
- 是否发布事件 / 埋点；
- 是否触发跨模块刷新；
- 是否写入 Storage；
- 是否启动或停止轮询 / WebSocket；
- 成功 / 失败后导航和局部状态如何变化。

这些常常是“主功能可用但迁移语义不完整”的来源。

## 输出

复杂模块使用 `../templates/02-功能清单.md` 与 `../templates/02-迁移模块功能点清单.md`；复杂前端页面的交互/布局契约按需使用 `../templates/08-页面结构与交互对齐清单.md`。同一个业务规则只维护在一个权威条目中，其他文档通过 ID 引用。
