# 11 源行为契约与开发对齐

## 目标

减少“文档理解正确，但开发过程中细节逐渐偏离源项目”的问题，同时避免和功能台账重复维护同一实施事实。

核心链路：

```text
源证据
→ 源行为
→ 目标决策
→ 功能子项
→ 实施
→ 验证证据
```

## 什么是源行为

源行为是用户、外部系统或业务流程可观察到的行为，不是文件、函数或框架机制。

常见维度包括：入口/前置条件、加载/空/错误/成功状态、字段显隐与格式、权限、校验、导航、状态流转、数据契约、响应式、无障碍和集成。

## 行为决策

```text
保持 / 目标修改 / 不迁移 / 未知
```

- `保持`：目标保留该可观察语义，实现方式可以目标原生；
- `目标修改`：必须记录批准后的目标期望行为；
- `不迁移`：记录依据；
- `未知`：影响当前方向时进入“必须询问”或阻塞。

## 风险与文档强度

- **低风险**：可把少量关键源行为直接记录在 `02`，不强制独立 `07`；
- **中风险**：关键源行为应有稳定 ID 和覆盖检查；
- **高风险**：完整源行为契约、输入基线、独立验证和必要集成验证。

## 与功能子项的权威边界

- `02-迁移模块功能点清单.md`：功能子项 **处理方式、实施状态、当前状态** 的权威源；
- `07-源行为与目标对齐清单.md`：源行为 **目标决策、覆盖、目标实际表现、验证状态、验证证据** 的权威源。

**不要在 `07` 中复制功能子项实施状态。** 源行为是否已经具备可验证实现，应通过关联功能子项读取。

## 源行为当前状态

源行为使用：

```text
未开始 / 待验证 / 验证中 / 验证失败
已完成 / 已阻塞 / 已延后 / 不适用
```

推导原则：

- 关联功能子项尚未满足处理要求 → `未开始`；
- 已满足处理要求但尚未验证 → `待验证`；
- 验证中 → `验证中`；
- 验证失败 → `验证失败`；
- 验证通过/不适用且处理要求满足 → `已完成`；
- 阻塞状态生效 → `已阻塞`；
- 不迁移 → `不适用`。

## 源行为覆盖检查门槛

中/高风险功能实施前检查：

- [ ] 关键源行为已盘点且有稳定 ID；
- [ ] 每条关键行为已有“保持 / 目标修改 / 不迁移 / 未知”决策；
- [ ] 所有“保持”行为至少映射一个范围内功能子项；
- [ ] 所有“目标修改”有明确目标期望行为；
- [ ] 权限、状态、错误、导航、数据契约等关键维度已覆盖；
- [ ] 不存在会改变当前实现方向的关键“未知”。

## 与功能子项的映射

例如：

```text
F-ORDER-I07
功能子项：返回订单列表后保留筛选条件
处理方式：修改现有
关联源行为：SB-ORDER-014
```

规则：

- “保持”行为没有功能子项 → 迁移遗漏；
- 功能子项没有源行为，也不是明确新增 → 检查来源依据；
- 一个源行为可映射多个强关联子项；
- 一个功能子项可覆盖多个紧密相关行为。

## 开发中对齐

开发过程以功能子项为实施单位：

```text
02：功能子项实施
→ 满足处理要求
→ 07：源行为进入待验证
→ 验证
→ 写入目标实际表现和验证证据
```

不要等整个功能完成后再一次性对照源项目。

## 验证失败

当 `验证状态=失败`：

```text
源行为当前状态 = 验证失败
```

如果失败同时阻塞后续开发，再设置：

```text
阻塞状态 = 已阻塞
当前状态 = 已阻塞
```

这样“验证失败”和“流程阻塞”是两个不同语义。

## 展示契约

高风险前端页面可补充展示契约，记录信息层级、区域顺序、主次操作、显示/隐藏/禁用、页面/弹窗/抽屉形态、响应式结构和关键视觉状态。

展示契约保护用户可感知结构，不要求像素级复制。

## 工作流输入基线

中/高风险长任务或多 Agent 工作流应记录源行为 / 目标期望行为基线。关键输入变化影响当前子项时暂停相关工作并重新校准。

## 验证负责人职责

验证负责人至少能回答：

- 保持行为是否真的存在于目标项目；
- 目标修改是否符合批准后的行为；
- 不迁移行为是否没有被错误恢复；
- 验证状态是否与实际运行一致；
- 是否存在未覆盖的关键源行为。

## 运行时产物

复杂中/高风险功能按需使用：

```text
.code-migration/07-源行为与目标对齐清单.md
```

低风险功能不机械创建本文件。
