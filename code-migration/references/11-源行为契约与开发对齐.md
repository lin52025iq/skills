# 11 源行为契约与开发对齐

## 目标

减少“文档理解正确，但开发过程中细节逐渐偏离 Source”的问题，同时明确模块化之后 Atomic Item、Source Behavior 和页面体验契约的权威边界。

```text
Source Evidence
→ Discovery / Provenance
→ Source Behavior
→ Target Decision
→ Atomic Item
→ Implementation
→ Behavior / Interaction / Structure Validation
```

## 模块化权威边界

模块化后：

```text
顶层 03
= Module Index / 派生进度 / links

modules/<module>/01-模块功能点.md
= Feature / Group / Atomic Item / 实施事实

modules/<module>/03-源行为对齐.md
= 模块私有 WHAT

modules/<module>/04-页面结构与交互.md
= 模块私有 HOW / WHERE
```

顶层 `05 / 06` 只维护全局或跨模块契约。

不要在顶层 `03` 和模块 `01` 双写 Atomic Item；不要在模块 `03/04` 与顶层 `05/06` 双写同一事实。

## 源行为之前先确认范围真实

中/高风险 Feature 先确认：

1. Discovery 已覆盖关键入口、条件分支、权限、Flag、反向调用、自动行为、测试和异常恢复；
2. 正式 Feature / Atomic Item 有合法 Provenance；
3. 当前 Module 的权威文件已经确定。

`推断候选 / 未知` 不得静默升级成必需范围。

## 行为决策

```text
保持 / 目标修改 / 不迁移 / 未知
```

关键“保持”行为必须映射至少一个范围内 Atomic Item；“目标修改”必须有明确 Target Behavior。

## WHAT 与 HOW / WHERE

模块私有：

```text
模块 03 = WHAT
模块 04 = HOW / WHERE
```

全局共享：

```text
顶层 05 = WHAT
顶层 06 = HOW / WHERE
```

例如：

```text
WHAT：409 后必须允许恢复
HOW：Drawer 不关闭、输入保留、Focus 如何表现
```

## 开发中对齐

```text
模块 01：确认 Atomic Item 来源与实施
→ 处理要求满足
→ 模块 03 / 顶层 05：验证 WHAT
→ 模块 04 / 顶层 06：验证 HOW / WHERE
→ 派生 Feature / Module 状态
→ 同步模块 00 Checkbox
→ 同步顶层 03 摘要
```

不要等整个页面结束后才一次性回看 Source。

## 新发现能力

发现新能力时：记录候选 → 判断来源 → 判断所属 Module / Feature → 拆 Atomic Item → 更新模块 `01` → 必要时补模块 `02/03/04` → 再实施。

不能把新能力直接塞进顶层 `03` 来绕过模块事实源。

## Checkbox

Checkbox 只是完成投影：

```text
Atomic Item 已完成 → Atomic [x]
Feature 已迁移/已清理 → Feature [x]
Module 已完成 → Module [x]
```

若 Checkbox 与模块 `01` 真实状态冲突，以真实状态为准并修正 Checkbox。

## 验证负责人职责

至少确认：

- 无来源功能没有混入正式范围；
- 关键保持行为均有 Atomic Item；
- 模块私有事实没有被重复写到顶层；
- WHAT / HOW-WHERE 边界清晰；
- Checkbox 没有覆盖真实失败；
- 顶层 `03` 派生摘要与模块 `00/01` 一致。

## 运行时产物

```text
低风险小模块：顶层 03 + 最小验证
中等模块：modules/<module>/00 + 01
中/高风险：按需增加模块 02/03/04
跨模块共享事实：顶层 04/05/06
```
