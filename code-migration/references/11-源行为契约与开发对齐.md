# 11 源行为契约与开发对齐

## 目标

减少“文档理解正确，但开发过程中细节逐渐偏离源项目”的问题。

核心链路：

```text
源证据
→ 源行为
→ 目标决策
→ 功能子项
→ 实施
→ 验证证据
```

任何关键“保持”行为如果在链路中断开，都可能成为迁移遗漏。

## 什么是源行为

源行为是用户、外部系统或业务流程可观察到的行为，不是文件、函数或框架机制。

常见维度：

- 入口 / 前置条件；
- 加载 / 空 / 错误 / 成功状态；
- 字段显示、隐藏、格式化；
- 权限 / 禁用 / 隐藏；
- 表单校验和错误恢复；
- 导航 / 深链接 / 前进后退；
- 状态流转和副作用；
- API / 数据契约；
- 弹窗 / 抽屉 / 提示；
- 响应式 / 无障碍；
- 埋点 / 集成。

例如：

```text
SB-ORDER-014
源行为：从订单详情返回列表后保留筛选条件
证据：C3 运行证据
```

## 行为决策

每条关键源行为使用：

```text
保持 / 目标修改 / 不迁移 / 未知
```

- `保持`：目标必须保留该可观察语义，但实现方式可以目标原生；
- `目标修改`：用户或目标产品明确改变，必须记录批准后的目标期望行为；
- `不迁移`：目标明确不需要，并记录依据；
- `未知`：证据不足，影响当前方向时进入“必须询问”或阻塞。

## 源行为子项状态

每条源行为必须直接维护 **当前状态**：

```text
未开始 / 开发中 / 待验证 / 验证中 / 已完成 / 已阻塞 / 已延后 / 不适用
```

同时维护：

```text
实施状态：未开始 / 实施中 / 已实施
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
阻塞状态：未阻塞 / 已阻塞
```

当前状态与 `02-迁移模块功能点清单.md`、`07-源行为与目标对齐清单.md` 使用同一套推导规则。

## 源行为覆盖检查门槛

功能从“已设计”进入“实施中”前检查：

- [ ] 关键源行为已盘点；
- [ ] 每条关键行为有稳定 ID；
- [ ] 每条关键行为已有“保持 / 目标修改 / 不迁移 / 未知”决策；
- [ ] 每条范围内行为已初始化当前状态、实施状态、验证状态和阻塞状态；
- [ ] 所有“保持”行为至少映射一个范围内功能子项；
- [ ] 所有“目标修改”有明确目标期望行为；
- [ ] 所有“不迁移”有明确依据；
- [ ] 权限、状态、错误、加载 / 空状态、导航、数据契约等关键维度已覆盖；
- [ ] 不存在会改变当前实现方向的关键“未知”。

## 与功能子项的映射

功能子项应引用源行为 ID，例如：

```text
F-ORDER-I07
功能子项：返回订单列表后保留筛选条件
关联源行为：SB-ORDER-014
迁移决策：保留
当前状态：开发中
实施状态：实施中
验证状态：未验证
```

规则：

- “保持”行为没有功能子项 → 迁移遗漏；
- 功能子项没有源行为，也不是明确“新增” → 检查来源依据；
- 一个源行为可映射多个强关联子项；
- 一个功能子项也可覆盖多个紧密相关行为；
- 不为了形式强制一对一。

## 开发中对齐

**不要等整个功能完成后再一次性对照源项目。**

```text
选择功能子项 / 源行为
→ 当前状态 = 开发中
→ 实施状态 = 实施中
→ 实施
→ 实施状态 = 已实施
→ 当前状态 = 待验证
→ 子项级验证
→ 验证状态 = 验证中 / 通过 / 失败 / 不适用
→ 同步当前状态
→ 写入验证证据
→ 再进入下一子项
```

如果实现中发现新的源细节：

1. 新增源行为；
2. 初始化当前状态和详细状态；
3. 判断行为决策；
4. 更新功能子项；
5. 判断是否影响工作流输入基线；
6. 影响时暂停相关子项并重新检查开始条件。

## 展示契约

前端复杂页面可为重要视觉 / 结构行为补充展示契约，例如：

- 信息层级；
- 区域顺序；
- 主次操作；
- 显示 / 隐藏 / 禁用；
- 页面 / 弹窗 / 抽屉形态；
- 响应式结构；
- 关键视觉状态。

展示契约保护用户可感知结构，不要求像素级复制；目标设计系统、间距、字体等默认按目标项目原生方式实现。

## 行为差异分类

```text
必须修复 / 已批准变化 / 目标原生差异 / 环境噪声 / 未知
```

不要把已批准变化修回源项目，也不要把真实行为回归误标成目标原生差异。

## 工作流输入基线

实施工作流开始时记录依赖的源行为 / 目标期望行为基线。

```text
变化不影响当前子项 → 记录后继续
变化影响当前子项 → 当前状态=已阻塞 → 更新基线 → 重新检查
```

这用于避免不同 Agent 基于不同版本的“正确文档”同时工作。

## 验证负责人职责

验证负责人应从源行为 / 目标决策出发独立验证，不以实施负责人说明作为唯一依据。

至少能回答：

- 保持行为是否真的存在于目标项目；
- 目标修改是否符合批准后的行为；
- 不迁移行为是否没有被错误恢复；
- 源行为 / 功能子项当前状态是否与实际代码和运行一致；
- 是否存在清单未覆盖的关键源行为。

## 运行时产物

复杂功能 / 模块按需使用：

```text
.code-migration/07-源行为与目标对齐清单.md
```

小功能可把源行为直接写入模块功能语义文档，不机械增加文档。
