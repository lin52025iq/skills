# 06 分阶段迁移与功能切片

## 目标

让 Agent 始终知道总体目标、当前阶段、当前功能、完成标准和下一步，避免同时铺开大量半成品。

## 执行层级

按任务规模选用：

- `L0 Context`：理解意图、源功能和目标约束；
- `L1 Foundation`：只做迁移必要的 Route、权限、API/类型等基础；
- `L2 Structure`：Page Shell、布局区域、响应式骨架、设计系统基础；
- `L3 Feature`：一个个完整用户能力；
- `L4 Integration`：跨模块、埋点、URL、缓存、全局导航等；
- `L5 Cutover`：切流、灰度、Route/Flag 切换；
- `L6 Cleanup`：旧实现、Adapter、Flag、依赖清理。

简单组件无需机械经历所有层级。

## 两层切片

前端默认区分：

### Structural Slice

只建立当前迁移范围必需的：Page Shell、主要 Region、Grid/Flex、Scroll owner、Responsive、基础 Token/Typography。

不要在结构阶段顺手实现所有业务细节。

### Functional Slice

以可独立解释、实现和验证的用户能力为单位，例如“订单列表查询”而不是“OrderTable.tsx”。紧密耦合的查询、分页、Loading/Error 可作为一个 Slice。

## 顺序模式

- `Layout-first`：目标布局/设计体系差异大，多个功能依赖共同骨架；
- `Feature-first`：目标页面已有，只迁某一能力；
- `Representative-slice-first`：大型、高风险或跨技术栈迁移，先做一个代表性切片验证规则。

不要把 Layout-first 误解为“先搭完整应用所有页面空壳”。只建立当前范围所需最小完整结构。

## 当前迁移焦点

每次实施必须维护：

```text
Overall Goal
Current Phase
Current Module / Region
Current Slice
Why Now
Dependencies
Do Not Touch
Definition of Done
Next Candidate
```

一次只有一个 `NOW`。其他任务处于 `READY / BLOCKED / DEFERRED / DONE`。

## Ready Gate

开始 Slice 前确认：功能语义、用户意图、目标落点、依赖和验证方法已经足够明确。关键 `UNKNOWN` 会改变实现方向时不得开始批量开发。

## Done Gate

至少确认：主流程和关键状态、Invariant、权限、数据、目标架构一致性和对应验证完成；没有静默扩大 Scope。

## 选择下一 Slice

优先级：

1. 最大幅度降低未知风险；
2. 解除其他 Feature 阻塞；
3. 用户明确优先；
4. 当前区域下一个完整能力；
5. 最后才是单纯最容易。

## Learning Loop

```text
Understand → Implement → Verify → Learn → Update Model → Next Slice
```

一个切片发现的通用规律，应先更新后续迁移方案，再扩大批次。
