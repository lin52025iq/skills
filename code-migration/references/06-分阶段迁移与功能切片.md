# 06 分阶段迁移与功能切片

## 目标

让 Agent 始终知道总体目标、当前阶段、当前功能、当前功能子项、完成标准和下一步，同时根据风险控制治理成本。前端迁移除了“功能能用”，还必须按风险控制**功能发现、交互语义和页面结构**的正确性。

## 风险分级

每个功能 / 工作流评估：

```text
低风险 / 中风险 / 高风险
```

- **低风险**：边界小、行为简单、目标项目已有稳定模式、无关键权限/资金/状态机/契约变化；
- **中风险**：存在较多状态、权限/错误/导航/数据契约，复杂交互或明显布局迁移；
- **高风险**：资金、权限、状态机、不可逆操作、多源冲突、跨技术栈大改、多 Agent 并行、复杂页面结构或高风险切流。

风险升级时立即补齐更高等级要求。

## 执行层级

- `L0 上下文`：意图、源功能和目标约束；
- `L1 公共基础`：迁移必要的路由、权限、API / 类型；
- `L2 结构`：页面区域树、布局、响应式、滚动 / Sticky / Overlay、设计系统基础；
- `L3 功能`：完整用户能力和关键交互；
- `L4 集成`：跨模块、URL、缓存、全局导航等；
- `L5 切流`：灰度、路由 / 功能开关切换；
- `L6 清理`：旧实现、Adapter、Flag、依赖清理。

简单组件无需机械经历所有层级。

## 前端四类覆盖

中/高风险前端功能进入大规模实施前，按适用性建立：

```text
功能发现覆盖
+ 源行为覆盖
+ 交互语义覆盖
+ 页面结构覆盖
```

分别回答：

- **功能发现覆盖**：有没有漏掉隐藏能力、条件逻辑、自动行为、副作用？
- **源行为覆盖**：已经发现的能力是否理解正确？
- **交互语义覆盖**：用户动作的触发、时序、反馈、恢复是否理解正确？
- **页面结构覆盖**：区域关系、布局、响应式和用户新布局方案是否明确？

低风险任务只做与风险相称的最小检查，不机械生成完整契约。

## 结构切片

中/高风险前端页面的结构切片顺序：

```text
观察源页面 / 读取用户新方案
→ 恢复源页面区域树
→ 提取布局不变量
→ 形成结构决策
→ 形成目标页面区域树
→ 搭最小结构骨架
→ 结构验证
→ 再进入大量功能切片
```

结构切片不是“先搭一堆空页面”，只建立当前范围需要的真实空间结构。

## 功能切片

以可独立解释、实现和验证的用户能力为单位，例如“订单退款完整交互”而不是某个组件文件。

一个功能切片可以包含强耦合的：

```text
触发条件 + UI 状态 + Mutation + 成功/失败 + 副作用 + 导航/恢复
```

不要把完整交互拆到无法单独验证的程度。

## 执行队列与功能点清单必须分离

`02-迁移模块功能点清单.md` 是 **范围、来源、处理方式和实施状态的事实源**；执行队列只负责调度。

## 功能子项状态

```text
当前状态：未开始 / 开发中 / 待验证 / 验证中 / 验证失败 / 已完成 / 已阻塞 / 已延后 / 不适用
处理方式：新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
实施状态：未开始 / 实施中 / 已实施 / 不适用
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
```

**验证失败必须显式映射为“当前状态=验证失败”，除非同时被阻塞规则覆盖为“已阻塞”。**

## 开始条件检查

### 低风险

- 功能 / 子项已进入台账；
- 每个正式子项有来源依据；
- 目标行为、处理方式、验证方式明确；
- 用户规则检查通过。

### 中风险

在低风险基础上增加：

- 功能发现覆盖检查；
- 关键源行为 ID 和源行为覆盖；
- 复杂交互的交互语义；
- 前端页面主要区域树 / 响应式结构；
- 子项级验证；
- 长任务输入基线。

### 高风险

在中风险基础上增加：

- 完整功能触点与反向追踪；
- 完整源行为契约；
- `08-页面结构与交互对齐清单.md`；
- 源页面可运行时优先 C3 页面 / 交互证据；
- 独立验证负责人或等价独立验证；
- 并行安全和工作区隔离；
- 工作流验证和必要集成验证；
- 回滚 / 清理条件。

## 功能发现真实性检查

正式范围内功能 / 子项至少具备一个合法来源：

```text
源系统证据 / 用户明确新增 / 目标产品要求 / 目标项目强制约束
```

`推断候选 / 未知` 不得静默进入 `范围内 + 必需=是`。

**目标项目有现成组件不等于目标产品需要对应功能。**

## 交互语义检查

复杂交互至少确认：

- 前置条件和触发方式；
- 即时反馈和中间状态；
- 重复提交 / 并发 / 取消；
- 成功 / 失败 / 恢复；
- 副作用；
- URL / Back / Focus / Keyboard / Scroll；
- 用户新交互方案是否覆盖旧交互。

## 页面结构检查

中/高风险页面至少确认：

- 页面主要区域和父子关系；
- 横向 / 纵向 / Grid / Overlay 关系；
- 关键宽度或列比例；
- 对齐和主要 Gap / Padding 层级；
- Scroll Owner、Sticky、Fixed；
- Modal / Drawer / Overlay；
- Desktop / Tablet / Mobile 的结构变化；
- 布局不变量；
- 用户新的布局方案已经形成目标页面结构。

## 用户新方案

用户明确的新功能、交互或布局方案不是 Source 回归。

目标优先级：

```text
用户当前明确方案
→ 目标产品要求
→ 必须保留的不变量
→ 目标项目稳定模式
→ Source 证据
→ 推断
```

Source C3 证明旧系统确实如何工作，但不能覆盖用户已经确认的新目标方案。

## 开发时同步更新

```text
选择功能子项
→ 检查来源真实性
→ 确认处理方式
→ 如需实施：开发中 → 已实施 → 待验证
→ 如复用已有/无需实施：直接待验证
→ 验证中
→ 通过：已完成
→ 失败：验证失败
→ 阻塞：已阻塞
→ 重新计算功能生命周期
```

如果实现中发现新的能力：先记录来源、重新执行发现覆盖和风险判断，再决定是否纳入当前范围。不能因为“顺手能做”直接实现。

## 文档权威边界

- `02`：功能范围、来源、处理方式、实施状态、当前状态；
- `07`：源行为决策、覆盖、目标实际表现、验证状态和证据；
- `08`：页面结构、交互语义、用户新 UX / 布局方案、结构 / 交互 / 视觉验证；
- `05`：执行调度和工作流。

## 完成条件检查

切片完成至少确认：

- 覆盖子项当前状态已更新；
- 所有范围内必需子项按处理方式达到完成条件；
- 不存在未处理的验证失败或阻塞；
- 要求的功能发现 / 源行为 / 交互 / 页面结构验证已完成；
- 没有无来源依据的新增能力混入完成范围；
- 功能生命周期已重新计算。

**切片已完成 ≠ 功能已迁移。**

## 选择下一切片

优先级：降低未知风险 → 解除其他功能阻塞 → 用户明确优先 → 当前区域下一个完整能力 → 单纯最容易。
