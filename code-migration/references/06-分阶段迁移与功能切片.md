# 06 分阶段迁移与功能切片

## 目标

让 Agent 始终知道总体目标、当前阶段、当前功能、当前功能子项、完成标准和下一步，同时根据风险控制治理成本，避免简单任务被过度流程化。

## 风险分级

每个功能 / 工作流评估：

```text
低风险 / 中风险 / 高风险
```

- **低风险**：边界小、行为简单、目标项目已有稳定模式、无关键权限/资金/状态机/契约变化；
- **中风险**：存在较多状态、权限/错误/导航/数据契约对齐，或需要跨会话推进；
- **高风险**：资金、权限、状态机、不可逆操作、多源冲突、跨技术栈大改、多 Agent 并行、共享契约或高风险切流。

风险升级时立即补齐更高等级要求。

## 执行层级

- `L0 上下文`：意图、源功能和目标约束；
- `L1 公共基础`：迁移必要的路由、权限、API / 类型；
- `L2 结构`：页面骨架、布局、响应式、设计系统基础；
- `L3 功能`：完整用户能力；
- `L4 集成`：跨模块、URL、缓存、全局导航等；
- `L5 切流`：灰度、路由 / 功能开关切换；
- `L6 清理`：旧实现、Adapter、Flag、依赖清理。

简单组件无需机械经历所有层级。

## 两层切片

### 结构切片

只建立当前迁移范围必需的页面骨架和布局，不顺手实现全部业务细节。

### 功能切片

以可独立解释、实现和验证的用户能力为单位，例如“订单列表查询”而不是某个组件文件。

## 执行队列与功能点清单必须分离

`02-迁移模块功能点清单.md` 是 **范围、处理方式和实施状态的事实源**；执行队列只负责调度。

## 功能子项状态

```text
当前状态：未开始 / 开发中 / 待验证 / 验证中 / 验证失败 / 已完成 / 已阻塞 / 已延后 / 不适用
处理方式：新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
实施状态：未开始 / 实施中 / 已实施 / 不适用
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
```

**验证失败必须显式映射为“当前状态=验证失败”，除非同时被阻塞规则覆盖为“已阻塞”。**

`复用已有 / 无需实施` 允许 `实施状态=不适用`，不能为了完成 Gate 伪造“已实施”。

## 功能生命周期

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

功能子项“已完成”不自动等于功能“已迁移”。功能必须汇总所有范围内必需子项及源行为验证结果。

## 开始条件检查

### 低风险

- 功能 / 子项已进入台账；
- 目标行为、处理方式、验证方式明确；
- 用户规则检查通过。

### 中风险

在低风险基础上增加：

- 关键源行为 ID；
- 源行为覆盖检查；
- 子项级验证；
- 长任务输入基线。

### 高风险

在中风险基础上增加：

- 完整源行为契约；
- 独立验证负责人或等价独立验证；
- 并行安全和工作区隔离；
- 工作流验证和必要集成验证；
- 回滚 / 清理条件。

## 开发时同步更新

```text
选择功能子项
→ 确认处理方式
→ 如需实施：开发中 → 已实施 → 待验证
→ 如复用已有/无需实施：直接待验证
→ 验证中
→ 通过：已完成
→ 失败：验证失败
→ 阻塞：已阻塞
→ 重新计算功能生命周期
```

## 02 与 07 的权威边界

- `02`：功能子项处理方式、实施状态、当前状态的权威源；
- `07`：源行为决策、覆盖、目标实际表现、验证状态和验证证据的权威源；
- `07` 不重复维护功能子项实施状态，只引用关联子项。

## 完成条件检查

切片完成至少确认：

- 覆盖子项当前状态已更新；
- 所有范围内必需子项按处理方式达到完成条件；
- 不存在未处理的验证失败或阻塞；
- 要求的源行为验证已完成；
- 功能生命周期已重新计算。

**切片已完成 ≠ 功能已迁移。**

## 选择下一切片

优先级：降低未知风险 → 解除其他功能阻塞 → 用户明确优先 → 当前区域下一个完整能力 → 单纯最容易。
