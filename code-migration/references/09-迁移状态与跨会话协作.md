# 09 迁移状态与跨会话协作

## 目标

让长周期迁移可以跨对话、跨 Agent 可靠续接，同时避免状态文档反过来主导迁移。`.code-migration/` 是迁移状态的持久化索引，不取代代码、测试、用户规则和已确认决策。

## 标准工作区顺序

```text
<target-repo>/.code-migration/
├── 00-迁移状态总览.md
├── 01-迁移任务上下文.md
├── 02-迁移约束与开发规则.md
├── 03-迁移模块功能点清单.md
├── 04-功能语义.md                  # 可选
├── 05-源行为与目标对齐清单.md      # 中/高风险按需
├── 06-页面结构与交互对齐清单.md    # 复杂前端按需
├── 07-功能融合映射.md              # 多来源按需
├── 08-迁移决策记录.md              # 重大决策按需
├── 09-迁移执行计划.md
└── modules/<module>/
```

顶层标准模板保持稳定编号；模块局部说明放在 `modules/<module>/`，不要创建与顶层用途重复的无序号文档。

## 事实源优先级

1. 用户最新明确迁移意图、新 UX / 交互 / 布局方案与约束；
2. `02` 生效规则和 `08` 已确认重大决策 / 目标产品契约；
3. 当前真实代码、Git、运行结果和测试；
4. `03` 范围 / Atomic Item / 实施事实；
5. `05` 行为验证事实、`06` 页面结构 / 交互验证事实；
6. `09` Workstream / 输入基线 / 临时 Batch；
7. `00` 状态总览。

`00` 是恢复入口和摘要缓存，不得覆盖更高优先级事实。

## 会话交接触发

以下情况同步状态：

- 当前 Workstream / 临时 Batch 完成；
- 准备暂停、结束或切换 Agent；
- 被“必须询问”阻塞；
- Discovery、用户新方案或重大 Decision 变化；
- 文档与代码 / Git 状态不一致。

至少记录：总体目标、风险级别、用户新方案、Discovery / 来源真实性、当前 Module / Feature / Atomic Item、`05 / 06` 验证状态、真实代码 / 测试状态、输入基线、阻塞 / 未知和下一安全动作。

## 新对话恢复

1. 读取 `00-迁移状态总览.md`；
2. 读取 `01-迁移任务上下文.md`，恢复目标和用户新方案；
3. 读取 `02-迁移约束与开发规则.md` 中所有生效规则；
4. 读取 `03-迁移模块功能点清单.md`，恢复范围和 Atomic Item 真实状态；
5. 按风险读取 `04 / 05 / 06 / 07 / 08`；
6. 读取 `09-迁移执行计划.md`，恢复 Workstream、输入基线和尚未结束的临时 Batch；
7. 核对 Git、工作区、代码和测试；
8. 不一致时只重新校准受影响范围；
9. 不重复开发已迁移项、不重复询问已有答案、不重新脑补已排除候选。

## 重新校准

以下情况标记 **需要重新校准**：

- 文档声称完成，但代码或测试不支持；
- 工作区存在未说明的半完成修改；
- 输入基线与最新 Discovery / 用户新方案 / Decision 不一致；
- `03 / 05 / 06` 对同一能力的范围或验证结论冲突。

重新校准只回答：哪些 Atomic Item 已完成、待验证、验证失败、半完成、未开始；哪些来源存疑；哪些契约过期；哪些 Workstream 输入过期；下一安全动作是什么。

## 多 Agent / Workstream

Workstream 是并行和所有权边界，不是新的产品层级。

推荐逻辑角色：协调、Source / Discovery、Target 架构、实施、验证、审查。环境不支持子 Agent 或安全隔离时，不伪造并行，保留 Workstream 模型并串行执行。

### 输入基线

中/高风险长任务按需记录：

```text
Discovery / Source Evidence 版本
用户新 UX / 布局方案版本
Target Behavior 版本
相关 Decision / 用户规则版本
目标落点
开始时 Git 提交
```

关键输入变化影响当前 Atomic Item 时：暂停 → 标记阻塞 → 更新基线 → 重跑受影响 Gate → 再继续。

### 并行安全

并行前检查：共享生产文件、Route/Layout/State/Query、API / 数据契约、权限 / 状态机、公共基础、lockfile、registry/generated、全局样式和发布依赖。

允许并行必须同时具备代码边界、数据 / 契约、业务语义、页面结构 / 交互和发布路径的足够独立性。

### 写入边界

- `03`：实施负责人维护自己拥有的 Atomic Item 实施事实；
- `05`：Source / 验证角色维护行为事实和验证；
- `06`：Target / 验证角色维护页面结构、交互目标和验证；
- `09`：协调角色维护 Workstream、输入基线和临时 Batch；
- `00`：协调角色汇总跨会话摘要。

同一事实块同一时刻只允许一个负责人。

## 集成验证

共享 Route/Layout、API/Query/State、权限、依赖/lockfile、Design System / 全局样式、registry/generated 或同一发布批次时执行必要集成验证。

各 Workstream 单独通过不代表整批迁移最终完成。

## 敏感信息

长期迁移默认让 `.code-migration/` 与代码一起进入版本控制，除非用户或 Target 规范明确要求不提交。

禁止写入 Token、Secret、Password、API Key、Cookie、Session、私钥、`.env` 真实值、真实客户敏感数据和不必要的生产 payload。
