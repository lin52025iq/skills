# 09 迁移状态与跨会话协作

## 目标

让长周期迁移可以跨对话、跨 Agent 可靠续接，同时保持**顶层导航简洁、模块事实局部化**。`.code-migration/` 是持久化索引，不取代代码、测试、用户规则和已确认 Decision。

## 标准工作区

```text
<target-repo>/.code-migration/
├── 00-迁移状态总览.md
├── 01-迁移任务上下文.md
├── 02-迁移约束与开发规则.md
├── 03-迁移模块索引与进度.md
├── 04-功能语义.md                  # 全局/跨模块按需
├── 05-源行为与目标对齐清单.md      # 全局/跨模块按需
├── 06-页面结构与交互对齐清单.md    # 全局/跨模块按需
├── 07-功能融合映射.md              # 多来源按需
├── 08-迁移决策记录.md              # 重大决策按需
├── 09-迁移执行计划.md
└── modules/<module>/
    ├── 00-模块总览.md
    ├── 01-模块功能点.md
    ├── 02-功能语义.md              # 按需
    ├── 03-源行为对齐.md            # 按需
    └── 04-页面结构与交互.md        # 按需
```

## 事实源优先级

1. 用户最新明确意图、新 UX / 交互 / 布局方案与约束；
2. `02` 生效规则和 `08` 已确认 Decision / Target 产品契约；
3. 真实代码、Git、运行和测试；
4. 模块化后的 `modules/<module>/01-模块功能点.md`，或未模块化小模块在顶层 `03` 的 Atomic Item 实施事实；
5. 模块内 `03 / 04` 或顶层 `05 / 06` 的验证事实；
6. `09` Workstream / 输入基线 / 临时 Batch；
7. 顶层 `03` 和 `00` 的派生摘要。

## 模块化恢复顺序

新对话恢复时：

1. 读取 `00-迁移状态总览.md`；
2. 读取 `01` 恢复目标和用户新方案；
3. 读取 `02` 生效规则；
4. 读取 `03-迁移模块索引与进度.md` 定位当前 Module；
5. 若模块已拆目录，点击/读取 `modules/<module>/00-模块总览.md`；
6. 读取该模块 `01-模块功能点.md` 恢复 Feature / Atomic Item 真实状态；
7. 按需读取模块内 `02–04`，全局共享事实才读取顶层 `04–06`；
8. 读取 `09` 恢复 Workstream、输入基线和未结束 Batch；
9. 核对 Git / 代码 / 测试；
10. 不一致时只重新校准受影响模块。

## Checkbox 恢复规则

Checkbox 不是状态事实。恢复时如果 `[x]/[ ]` 与真实状态不一致：

```text
以真实 Atomic Item / Feature / Module 状态为准
→ 修正 Checkbox
```

不得反过来以 Checkbox 覆盖实施或验证状态。

## 会话交接触发

以下情况同步状态：Workstream/Batch 完成、准备暂停或切换 Agent、被必须询问阻塞、用户新方案或 Decision 变化、文档与代码不一致。

至少记录：当前 Module 入口、Feature / Atomic Item、真实实施/验证状态、当前 Workstream、尚未结束 Batch、输入基线、阻塞/未知和下一安全动作。

## 重新校准

以下情况标记 **需要重新校准**：

- 顶层 `03` 摘要与模块 `00/01` 不一致；
- Checkbox 与真实状态不一致；
- 模块文档链接失效；
- 文档声称完成但代码/测试不支持；
- 输入基线与最新 Discovery / 用户新方案 / Decision 不一致；
- 模块内 WHAT/HOW-WHERE 契约与实现不一致。

重新校准只修受影响 Module，不重新扫描全部迁移。

## 模块拆分与合并

当原本留在顶层 `03` 的小模块变复杂时：

```text
创建 modules/<module>/00 + 01
→ 把详细 Feature / Atomic Item 移入模块 01
→ 顶层 03 改为链接和摘要
→ 按需创建模块 02/03/04
```

迁移后不得继续在顶层和模块 `01` 双写同一 Atomic Item 状态。

## 多 Agent / Workstream

Workstream 是并行和所有权边界，不是产品层级。模块目录天然可以作为协作边界，但并行前仍检查共享 Route/Layout/State/Query、API/契约、权限/状态机、公共基础、lockfile、registry/generated 和全局样式。

环境不支持子 Agent 或安全隔离时，不伪造并行，保留 Workstream 模型并串行执行。

### 写入边界

- 模块 `01`：实施负责人维护 Atomic Item 实施事实；
- 模块 `03` / 顶层 `05`：行为验证；
- 模块 `04` / 顶层 `06`：页面结构和交互验证；
- `09`：协调角色维护 Workstream / Batch；
- 模块 `00`、顶层 `03`、顶层 `00`：派生摘要与导航。

## 集成验证

共享 Route/Layout、API/Query/State、权限、依赖/lockfile、Design System / 全局样式、registry/generated 或同一发布批次时执行必要集成验证。

各模块或 Workstream 单独通过不代表整批迁移最终完成。

## 敏感信息

长期迁移默认让 `.code-migration/` 与代码一起进入版本控制，除非用户或 Target 规范明确要求不提交。禁止写入 Secret、Token、Password、Cookie、Session、私钥、`.env` 真实值和真实客户敏感数据。
