# 08 验证切流与遗留清理

## 目标

证明迁移后的目标能力正确，并让旧实现能够安全退出。验证对象是 **目标期望行为**，不是默认要求新系统逐项复刻旧系统。

## 验证基准

先根据迁移决策确定“什么叫正确”：

- `保留`：关键旧能力、业务规则和 Invariant 未丢失；
- `适配`：保留必要旧语义，同时验证批准后的目标调整；
- `合并`：验证统一后的目标语义；
- `替换 / 新增`：验证新的目标契约；
- `移除`：验证旧入口 / 调用方被安全移除；
- `复用目标`：验证目标已有能力满足当前功能契约。

已确认产品变化应记录为 **“已批准变化”**，不要把它当成回归修回旧行为。

## 验证维度

按风险组合：

- 业务主流程与 Invariant；
- 加载 / 空 / 错误 / 成功状态；
- 权限、功能开关、深链接；
- API、数据、枚举、时间、金额和错误契约；
- 单元 / 组件 / 集成 / 端到端测试；
- 视觉、响应式、键盘、焦点、无障碍；
- SSR / hydration、控制台、网络、运行时；
- 性能、包体积、SEO、安全、埋点和监控。

## 差异分类

发现差异时分类：

```text
必须修复 / 已批准变化 / 环境噪声 / 未知
```

- `必须修复`：偏离目标期望行为；
- `已批准变化`：明确接受的目标变化；
- `环境噪声`：与迁移语义无关的环境差异；
- `未知`：尚不能判断是否正确。

不要通过放宽截图阈值、跳过测试或删除断言把真实回归变成“通过”。

## 生命周期状态

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

- `实施中`：正在开发，不能视为完成；
- `验证中`：主要实现已完成，但验证条件尚未满足；
- `已迁移`：目标实现已完成，并已证明满足当前目标期望行为；
- `已清理`：流量 / 入口已切换，旧路由、旧实现、Adapter、功能开关、重复依赖、临时数据路径和相关测试 / 文档已按计划清理。

`已阻塞` 是附加状态，不替代生命周期。

## 切流

高风险迁移应明确：

- 切流单位和时间；
- 用户分组 / 功能开关 / 路由切换；
- 观测指标；
- 回滚动作；
- 回滚所需数据兼容性；
- 负责人和判断条件。

## 遗留清理检查门槛

删除旧实现前确认：

- 新入口满足目标行为并稳定；
- 没有仍在使用的调用方；
- 回滚窗口要求已满足；
- 临时 Adapter / 功能开关的删除条件已达成；
- 旧依赖和资源可安全移除；
- 文档、测试和监控已指向目标实现。

迁移报告应区分 **“验证中 / 已迁移 / 已清理”**，不要把“代码基本写完”混同为迁移完成。
