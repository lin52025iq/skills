# 中文事实模型与模块升级

本文定义 `code-migration` 工作区中稳定的中文字段、枚举、权威事实边界，以及模块从顶层内联升级为独立目录的规则。

## 1. 原则

1. 状态、枚举和值优先使用中文，避免同一概念出现多套近义表达。
2. 规范只定义字段和值，不另建 JSON/YAML 状态文件；真实迁移事实仍维护在对应 Markdown 权威文件中。
3. 同一详细事实只维护一处。摘要、Checklist 和进度表均为派生视图。
4. 模块目录是承载方式，不是模块身份。模块、功能、原子功能项编号在迁移过程中保持稳定。
5. 小模块允许先在顶层 `03` 内联维护，复杂度上升后再迁入独立模块目录。
6. 公共模块只承载跨业务模块复用、具有业务或用户可观察语义、可独立实施和验证的公共能力。
7. 状态收敛必须从详细权威事实向上单向进行，任何摘要、Checklist、工作流状态都不能反向覆盖详细事实。

## 2. 实体层级

```text
模块
└─ 功能
   ├─ 功能组 / 场景组（可选）
   │  ├─ 原子功能项
   │  └─ 原子功能项
   └─ 原子功能项
```

公共模块使用相同的“功能 → 原子功能项”模型，只是由多个业务模块引用。

## 3. 模块规范

建议字段：

```text
模块编号
模块名称
承载方式
风险级别
模块状态
用户目标
用户新方案
权威位置
当前功能
下一安全动作
```

枚举：

```text
承载方式：顶层内联 / 独立模块 / 公共模块
风险级别：低风险 / 中风险 / 高风险
模块状态：未开始 / 进行中 / 验证中 / 已完成 / 已阻塞
```

推荐独立模块目录：

```text
modules/M-001-订单中心/
modules/M-002-用户管理/
```

编号提供稳定身份，中文名称提供可读性。

## 4. 功能规范

建议字段：

```text
功能编号
功能名称
用户目标
目标行为
风险级别
来源类型
来源依据
迁移决策
发现状态
源行为契约
页面结构与交互契约
公共功能依赖
完成定义
生命周期
```

枚举：

```text
生命周期：已发现 / 已设计 / 实施中 / 验证中 / 已迁移 / 已清理
发现状态：未检查 / 部分通过 / 通过 / 未通过 / 不要求
```

## 5. 原子功能项规范

必需字段优先保持简洁；只有复杂、失败、阻塞或需要审计的项才展开全部字段。

建议字段：

```text
原子功能项编号
名称
当前状态
范围状态
是否必需
来源类型
来源依据
迁移决策
处理方式
实施状态
验证状态
阻塞状态
关联源行为
关联页面体验
关联集成验证
验证方式 / 证据
失败原因 / 下一动作
```

统一枚举：

```text
当前状态：
未开始 / 开发中 / 待验证 / 验证中 / 验证失败 / 已完成 / 已阻塞 / 已延后 / 不适用

范围状态：
范围内 / 范围外 / 待确认

是否必需：
是 / 否

来源类型：
源系统证据 / 用户明确新增 / 目标产品要求 / 目标项目强制约束 / 推断候选 / 未知

迁移决策：
保留 / 修改 / 替换 / 新增 / 删除 / 合并 / 待决定

处理方式：
新增实现 / 修改现有 / 复用已有 / 无需实施 / 删除旧实现

实施状态：
未实施 / 实施中 / 已实施 / 无需实施

验证状态：
未验证 / 验证中 / 通过 / 失败 / 不要求

阻塞状态：
未阻塞 / 已阻塞
```

不要使用“差不多完成”“基本完成”“等待看看”等非规范状态。

## 6. 原子功能项状态收敛

`当前状态` 是由详细事实收敛出的综合状态，不应与 `实施状态 / 验证状态 / 阻塞状态` 分别手工维护成互相矛盾的事实。

按以下优先级自上而下判定，命中后停止：

| 优先级 | 条件 | 当前状态 |
|---:|---|---|
| 1 | `范围状态 = 范围外`，或明确判定该项对当前目标不适用 | `不适用` |
| 2 | `当前状态` 已被明确决策为 `已延后` | `已延后` |
| 3 | `阻塞状态 = 已阻塞` | `已阻塞` |
| 4 | `验证状态 = 失败` | `验证失败` |
| 5 | `验证状态 = 验证中` | `验证中` |
| 6 | `验证状态 = 通过` | `已完成` |
| 7 | `实施状态 = 已实施 / 无需实施` 且 `验证状态 = 不要求` | `已完成` |
| 8 | `实施状态 = 已实施 / 无需实施` 且 `验证状态 = 未验证` | `待验证` |
| 9 | `实施状态 = 实施中` | `开发中` |
| 10 | `实施状态 = 未实施` | `未开始` |

补充约束：

- `范围状态 = 待确认` 时，不得派生为 `已完成`；先解决范围真实性。
- `来源类型 = 推断候选 / 未知` 且尚未确认来源时，不得作为必需项推进到最终完成。
- `处理方式 = 复用已有 / 无需实施` 不代表验证通过；只有 `验证状态 = 通过 / 不要求` 才能完成。
- `已延后` 必须有明确决策或范围安排，不能用来隐藏失败、阻塞或未实施。
- 如果详细字段与 `当前状态` 冲突，以详细字段和已确认决策为准，重新派生 `当前状态`。

## 7. 功能生命周期收敛

功能生命周期不是独立的自由输入。除 `已清理` 需要清理事实外，其余生命周期主要由范围内必需原子功能项、发现状态、契约验证、公共依赖和集成验证共同收敛。

推荐判定顺序：

```text
未满足设计入口
→ 已发现

范围和目标行为已明确，但尚未开始实施
→ 已设计

任一必需原子功能项 = 开发中 / 未开始，且已经进入实施
→ 实施中

全部必需原子功能项已实施或无需实施，仍有待验证 / 验证中 / 验证失败
→ 验证中

全部范围内必需原子功能项 = 已完成
+ 要求的发现工作满足
+ 要求的源行为验证通过
+ 要求的页面结构与交互验证通过
+ 必要公共功能依赖满足
+ 必要集成验证通过
→ 已迁移

已迁移
+ 旧入口 / 旧实现 / 临时兼容 / Feature Flag 等要求的清理完成
→ 已清理
```

硬约束：

- 任一范围内必需原子功能项为 `验证失败 / 已阻塞 / 未开始 / 开发中 / 待验证 / 验证中` 时，功能不得为 `已迁移 / 已清理`。
- 公共功能依赖未满足时，依赖它的功能不得为 `已迁移`。
- 要求的行为、交互或集成验证失败时，功能不得为 `已迁移`。
- `已清理` 只能从 `已迁移` 继续推进，不能跳跃。

## 8. 模块状态收敛

模块状态只由其范围内必需功能及模块级集成条件派生：

```text
全部功能尚未进入实施
→ 未开始

存在功能处于 已发现 / 已设计 / 实施中
→ 进行中

不存在实施中功能，但存在功能处于 验证中
→ 验证中

任一必需功能因真实阻塞无法推进
→ 已阻塞

全部范围内必需功能达到要求生命周期
+ 模块共享边界的必要集成验证通过
+ 模块级目标成立
→ 已完成
```

其中“达到要求生命周期”默认至少为 `已迁移`；如果当前迁移目标明确包含遗留清理，则要求相关功能达到 `已清理`。

优先级建议：

```text
已阻塞
> 验证中
> 进行中
> 未开始
> 已完成（只有全部完成条件同时成立时才可进入）
```

`已完成` 不能通过“多数功能完成”或“当前批次完成”推导。

## 9. 依赖阻断与完成条件

功能可以引用其他功能或公共功能作为前置依赖：

```text
依赖功能：F-xxx / 无
公共功能依赖：公共-xxx / 无
```

依赖只记录稳定编号，不复制被依赖项内部状态。

收敛规则：

- 前置依赖未达到当前功能所需状态时，当前功能可以继续做不受影响的工作，但不得跨过依赖相关完成门。
- 公共功能依赖未满足时，业务模块只记录“依赖未满足”，不复制公共功能内部失败或验证表。
- 依赖变化后，只重新校准受影响功能、模块和验证范围，不无差别重算全部工作区。

## 10. 派生视图收敛顺序

每次实施、验证、范围决策、公共依赖或集成结果变化后，按固定顺序收敛：

```text
1. 更新详细权威事实
2. 重新派生原子功能项当前状态
3. 重新派生功能生命周期
4. 重新派生模块状态
5. 同步模块 00 摘要 / Checklist
6. 同步顶层 03 模块摘要 / Checklist
7. 同步顶层 00 恢复游标中的当前状态
8. 更新 09 工作流 / 执行批次的执行视图
```

注意：`09` 的工作流或执行批次可以有自己的执行状态，但不能成为功能或模块完成状态的事实来源。

## 11. 冲突修正规则

发生不一致时，按以下权威顺序裁决：

```text
详细权威事实 / 已确认决策
>
原子功能项当前状态
>
功能生命周期
>
模块状态
>
模块 00 / 顶层 03 摘要
>
顶层 00 恢复摘要
>
09 执行视图
>
Checkbox
```

例如：

```text
模块 01：I03 验证状态 = 失败
模块 00：退款功能 [x]
顶层 03：订单模块 = 已完成
```

正确处理：

```text
确认 I03 详细事实
→ I03 当前状态 = 验证失败
→ 功能生命周期 = 验证中
→ 模块状态重新派生
→ 修正模块 00
→ 修正顶层 03
→ 修正 Checkbox
```

禁止为了让上层摘要“看起来一致”而把下层真实失败改成完成。

## 12. 三种承载方式

### 顶层内联

适合低风险、小体量、没有独立维护价值的模块。

```text
03-迁移模块索引与进度.md
└─ M-008 通知设置
   └─ F-001 邮件通知
      ├─ F-001-I01
      └─ F-001-I02
```

该模块对应章节就是详细权威事实源。

### 独立模块

适合跨会话、多个功能、独立验证或独立工作流的模块。

```text
modules/M-008-通知设置/
├── 00-模块总览.md
├── 01-模块功能点.md
├── 02-功能语义.md          # 按需
├── 03-源行为对齐.md        # 按需
└── 04-页面结构与交互.md    # 按需
```

其中 `01-模块功能点.md` 是详细功能和原子功能项的权威事实源。

### 公共模块

```text
modules/shared/
├── 00-公共模块总览.md
└── 01-公共功能点.md
```

公共功能必须同时满足：

- 被两个或以上业务模块实际依赖，或明确预期作为跨模块能力；
- 有独立业务或用户可观察语义；
- 能独立判断实施和验证。

普通 UI 组件、工具函数、Hook、样式和纯工程基础设施不登记为公共功能点。

## 13. 模块升级规则

模块从顶层内联升级成独立模块时：

```text
承载位置变化
≠ 模块身份变化
≠ 功能重建模
```

必须保持：

```text
模块编号不变
功能编号不变
原子功能项编号不变
已确认的来源和迁移决策不变
历史验证和决策引用仍可追踪
```

推荐步骤：

1. 创建 `modules/M-xxx-模块名称/00-模块总览.md` 和 `01-模块功能点.md`。
2. 原样迁移详细功能、原子功能项和真实状态。
3. 检查所有编号和语义未变化。
4. 更新 `09`、决策、验证证据中的路径引用。
5. 将顶层 `03` 中详细内容删除，只保留模块派生摘要和真实入口链接。
6. 检查不存在两份同时可写的详细事实。
7. 按“派生视图收敛顺序”重新同步所有摘要与 Checklist。

## 14. 升级触发条件

不设置机械的固定数量阈值。以下任一情况成立时优先升级：

- 多个功能需要独立追踪；
- 原子功能项平铺后明显影响顶层可读性；
- 需要跨会话持续推进；
- 需要独立工作流或并行边界；
- 需要模块私有功能语义、源行为或页面结构/交互契约；
- 风险较高，需要独立验证或集成结论；
- 多人或多个 Agent 会持续修改；
- 顶层章节已经明显干扰其他模块浏览。

## 15. 公共功能引用

业务模块只保存依赖关系，不复制公共功能详细状态。例如：

```text
公共功能依赖：
- 公共-PERM-001 权限校验
- 公共-NOTIFY-002 操作结果通知
```

公共功能的实施和验证状态只在 `modules/shared/01-公共功能点.md` 更新。业务模块需要记录的是“该公共依赖是否满足当前功能完成条件”，而不是复制公共功能内部状态表。
