# 10 用户约束与开发规则

## 目标

让用户能够在整个迁移过程中持续定义、修改和暂停执行规则，使 Agent 不只知道“迁什么”，还知道“迁移时必须怎样做、禁止怎样做、什么情况下需要先确认”。

规则运行时实例写入目标项目：

```text
.code-migration/06-迁移约束与开发规则.md
```

模板源文件见 `templates/06-迁移约束与开发规则.md`。

## 规则的四个要素

每条规则应包含：

```text
作用域 + 触发条件 + 强度 + 动作/约束
```

例如：

```text
作用域：订单模块
触发条件：执行 UI 回归
强度：必须
动作：必须使用 Playwright
```

不要只写“最好用 Playwright”这类无法判断是否满足的模糊约束。

## 强度

只使用中文状态：

```text
必须 / 禁止 / 必须询问 / 建议
```

- `必须`：触发时必须满足，否则当前操作不得继续；
- `禁止`：触发时不得执行；
- `必须询问`：执行前需要用户确认；
- `建议`：默认优先，但允许依据目标仓库证据合理偏离。

## 作用域

支持：

```text
全局 / Module / Feature / Feature Item / Slice
```

具体作用域规则优先于更宽泛规则。例如订单 Feature 的规则可以覆盖全局“建议”规则，但不得静默覆盖用户全局“禁止”规则；出现强约束冲突时进入澄清。

## 可以约束什么

### 工具

例如：

- 禁止使用某个命令或工具；
- 指定代码搜索必须使用某个工具；
- UI 回归必须使用 Playwright；
- 批量 Codemod 前必须询问；
- 不允许执行某类自动修改。

### 技术与实现

例如：

- 禁止新增 Redux；
- 必须复用目标项目 Query client；
- 不允许新增第二套 API client；
- 必须使用现有 Design System；
- 某模块禁止引入新依赖；
- 某类功能必须放在指定模块中。

### 测试与验证

例如：

- Feature 进入“验证中”必须执行 E2E；
- 所有页面必须验证响应式；
- 不允许通过降低测试阈值让失败变通过；
- 某类修改必须同时补单测和集成测试。

### 用户确认

例如：

- 修改 API contract 前必须询问；
- 删除旧功能前必须确认；
- 修改权限规则前必须确认；
- 引入新依赖前必须确认。

## 规则来源与优先级

执行时按以下顺序理解约束：

1. 用户最新明确规则；
2. 已确认 Decision；
3. 目标仓库强制规范和仓库级指令；
4. `.code-migration/06-迁移约束与开发规则.md` 中仍“生效中”的规则；
5. Agent 默认偏好。

如果高优先级规则彼此冲突，不自行选择，进入 Clarification Loop。

## Ready Gate 集成

每个 Slice 开始前：

1. 根据当前 Module / Feature / Feature Items / Slice 过滤生效规则；
2. 判断哪些规则被当前操作触发；
3. `必须` 未满足 → 不得开始；
4. `禁止` 会被违反 → 改方案；
5. `必须询问` 尚未确认 → 当前相关操作进入已阻塞并询问用户；
6. `建议` 若偏离 → 记录原因。

规则检查不能在代码写完后补做。

## 开发中动态新增规则

用户可以在迁移任意时刻增加规则，例如：

> 后面所有页面都不要使用新的状态库。

Agent 应立即：

1. 判断这是长期规则还是仅当前请求；
2. 若是长期规则，写入 `06-迁移约束与开发规则.md`；
3. 标记作用域、触发条件、强度、状态和来源；
4. 检查当前和待执行 Slice 是否受影响；
5. 如果已有实现违反新规则，记录受影响范围并与用户确认是返工、豁免还是仅对后续生效。

不要静默把新规则追溯应用到所有历史代码。

## 规则生命周期

```text
生效中 / 已暂停 / 已失效
```

规则变更应保留变化记录。用户改变主意时不要删除旧规则导致后续无法理解历史实现原因。

## 与功能台账的关系

规则文件定义“怎样开发”；`02-迁移模块功能点清单.md` 定义“需要开发什么以及做到哪一步”。

两者不要合并。

如果某 Feature Item 受到特定规则约束，可在 Item 的 Notes 或关联规则字段引用 Rule ID，例如：

```text
F-ORDER-I03 → TOOL-002, TEST-004
```

## 跨对话恢复

新对话继续迁移时，读取状态总览和当前模块后，必须读取所有“生效中”的相关规则，再继续开发。

规则是跨对话持久化约束，不能只依赖聊天历史。
