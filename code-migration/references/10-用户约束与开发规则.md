# 10 用户约束与开发规则

## 目标

让用户在迁移过程中持续定义、修改和暂停执行规则，使 Agent 不只知道“迁什么”，还知道“怎样做、禁止怎样做、什么情况下必须先确认”。

运行时规则写入：

```text
.code-migration/02-迁移约束与开发规则.md
```

## 规则四要素

```text
作用域 + 触发条件 + 强度 + 动作 / 约束
```

强度：

```text
必须 / 禁止 / 必须询问 / 建议
```

作用域：

```text
全局 / 模块 / 功能 / 原子功能项 / 工作流
```

## 可以约束什么

### 工具

例如：禁止某工具、指定搜索工具、UI 回归必须用 Playwright、批量 Codemod 前必须询问。

### 技术与实现

例如：禁止新增第二套状态/API Client、必须复用 Target Query Client/Design System、限制依赖和模块边界。

### 测试与验证

例如：关键 Atomic Item 进入验证必须执行 E2E、页面必须验证响应式、禁止降低测试阈值掩盖失败。

### 用户确认

例如：修改 API 契约、删除旧能力、修改权限、引入高风险依赖前必须确认。

## 规则来源与优先级

1. 用户当前最新且有效的明确指令；
2. `08-迁移决策记录.md` 中已确认 Decision；
3. Target 仓库强制规范和安全约束；
4. `02-迁移约束与开发规则.md` 中生效中的历史规则；
5. Agent 默认偏好。

高优先级规则冲突时进入澄清，不自行选择。

## Ready Gate 集成

每个 Workstream / 临时 Batch 开始前：

1. 根据当前 Module / Feature / Atomic Item / Workstream 过滤生效规则；
2. 判断当前操作触发哪些规则；
3. `必须` 未满足 → 不得开始；
4. `禁止` 会被违反 → 改方案；
5. `必须询问` 尚未确认 → 标记相关 Atomic Item / Workstream 已阻塞；
6. `建议` 若偏离 → 记录原因。

规则检查不能在代码写完后补做。

## 指定工具不可用

用户规则要求必须使用某工具时，先确认工具、权限、连接和环境可用性。

如果不可用：

1. 不静默改用其他工具；
2. 相关 Atomic Item / Workstream 标记已阻塞；
3. 记录原因和解除条件；
4. 向用户说明；
5. 用户决定启用、允许替代、修改规则或延后。

## 动态新增规则

用户可随时增加规则。Agent 判断其是否为长期规则；长期规则写入 `02`，记录作用域、触发条件、强度、状态和来源，并检查当前 / 待执行工作是否受影响。

不要静默追溯应用到所有历史代码。

## 规则生命周期

```text
生效中 / 已暂停 / 已失效
```

规则变更保留记录。

## 与功能台账关系

`02` 定义 **怎样开发**；`03-迁移模块功能点清单.md` 定义 **开发什么以及做到哪一步**。两者不要合并。

Atomic Item 可以引用规则 ID，例如：

```text
F-ORDER-I03 → TOOL-002, TEST-004
```

## 跨对话恢复

新对话：读取 `00` → `01` → `02` 生效规则 → `03` 当前 Atomic Item / Workstream 范围 → 检查当前用户最新指令、`08` Decision 和 Target 强制规则 → 再继续实施。
