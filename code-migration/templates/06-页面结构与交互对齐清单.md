## 边界

```text
05 = WHAT
06 = HOW USER EXPERIENCES IT + WHERE
```

例如：

```text
05：409 后必须允许用户恢复操作
06：Drawer 不关闭、输入保留、错误提示和 Focus 如何表现

05：返回列表后必须保留用户上下文
06：filter/page/scroll/focus 具体如何恢复
```

只为迁移风险值得独立追踪的交互 / 区域建立 INT / REG ID，不机械为每个按钮、字段或普通容器建 ID。

## 目标优先级

```text
用户当前明确的新 UX / 布局方案
→ 目标产品要求
→ 必须保持的交互 / 布局 Invariant
→ Target 稳定 Design System / Layout Pattern
→ Source C3/C2
→ Source C1
→ 推断
```

C3 证明 Source 的真实体验，不代表 Target 必须照抄。

## Ready Gate

- [ ] 用户新方案已经进入 Target 结构 / 交互；
- [ ] 关键区域树和主要空间关系明确；
- [ ] 关键响应式变化明确；
- [ ] Scroll / Sticky / Overlay 等重要边界明确；
- [ ] 关键交互时序和恢复语义明确；
- [ ] 不存在会改变 Target UX 方向的关键未知。

高风险且 Source 可运行时，优先使用实际页面、多 Viewport 和真实交互 C3 证据；不只依赖静态源码猜测。

## 验证

### 结构

- [ ] Target 区域树正确；
- [ ] 关键排列 / 比例 / Scroll / Sticky 正确；
- [ ] 响应式结构正确；
- [ ] 用户批准的新布局正确落地。

### 交互

- [ ] 关键触发和中间状态正确；
- [ ] 成功 / 失败 / 恢复正确；
- [ ] 必要副作用、URL、Focus、Keyboard、Scroll 体验正确；
- [ ] 用户批准的新交互正确落地。

## 差异分类

```text
结构错误 / 交互错误 / 视觉错误
已批准结构变化 / 已批准交互变化
目标原生差异 / 环境噪声 / 未知
```

用户已批准的新方案不是回归，不得为了贴近 Source 修回旧形态。

## 验证摘要

- 结构验证：`未验证 / 验证中 / 通过 / 失败 / 不适用`
- 交互验证：`未验证 / 验证中 / 通过 / 失败 / 不适用`
- 响应式验证：`未验证 / 验证中 / 通过 / 失败 / 不适用`
- 关键视觉验证：`未验证 / 验证中 / 通过 / 失败 / 不适用`
