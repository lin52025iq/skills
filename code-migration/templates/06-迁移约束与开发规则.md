# 迁移约束与开发规则

> 这是迁移过程中由用户、目标项目或已确认 Decision 定义的长期执行规则。规则可以约束工具、技术方案、代码组织、测试、操作方式和必须确认的行为。长周期迁移中新对话必须读取本文件后再继续实施。

## 使用原则

1. 用户明确规则优先于 Agent 偏好；与目标项目强制规范冲突时必须显式指出并进入澄清，不得静默选择。
2. 规则必须尽量写成可判断是否满足的形式，避免“尽量”“最好”等无法验证的描述。
3. 每条规则必须标明作用域、触发条件和强度；没有触发时不扩大解释。
4. `必须` 和 `禁止` 属于强约束；违反前不得继续对应操作。
5. `必须询问` 表示触发条件成立时需要用户确认；回答后可沉淀为新的规则或 Decision。
6. `建议` 是默认偏好，有充分目标项目证据时允许偏离，但应记录原因。
7. 规则变化要更新状态，不删除历史依据；已失效规则标记“已失效”。
8. 不把一次性聊天偏好自动升级为永久规则；只有用户明确要求长期约束、目标项目规范或已确认 Decision 才写入本文件。
9. 用户当前对话中的最新明确指令高于本文件中的旧规则；如果用户修改旧规则，要同步更新规则状态或变更记录。

## 规则强度

```text
必须 / 禁止 / 必须询问 / 建议
```

- `必须`：触发条件成立时必须执行；
- `禁止`：触发条件成立时不得执行；
- `必须询问`：执行前需要用户确认；
- `建议`：优先采用，但允许有证据地偏离。

## 规则状态

```text
生效中 / 已暂停 / 已失效
```

## 作用域

规则作用域可以是：

```text
全局 / Module / Feature / Feature Item / Slice
```

作用域越具体，匹配越精确；但具体规则不能静默覆盖更高优先级的用户明确“必须/禁止”。出现强约束冲突时进入澄清。

## 工具使用规则

用于明确“不能使用什么工具”或“什么场景必须使用什么工具”。

|---|---|---|---|---|---|---|---|
| TOOL-001 | 全局 | 搜索代码 | 不使用某工具 | `禁止` | 使用目标仓库已有搜索方式 | `生效中` |  |
| TOOL-002 | Module:M-001 | 执行 UI 回归 | 使用 Playwright | `必须` | 无 | `生效中` |  |

工具规则示例：

```text

强度 = 禁止

替代 = 使用用户指定搜索工具

条件 = 迁移页面完成后做浏览器验证

作用域 = 全局
条件 = 需要批量修改代码
强度 = 必须询问
规则 = 使用 Codemod 前先向用户确认
```

### 指定工具不可用

当“必须”规则要求使用指定工具时，先确认：

- 工具是否存在；
- 是否具备所需权限、授权或连接；
- 当前仓库/环境是否支持；
- 是否能够完成规则要求的操作或验证。

如果不可用、权限不足或环境不支持：

```text
相关 Slice / Feature Item = 已阻塞
```

并记录：

- 阻塞原因；
- 解除条件；
- 当前不可用的工具；
- 可选替代方案（如有）。

不得静默改用替代工具。由用户决定启用/提供工具、允许替代、修改规则或延后操作。

| Rule ID | 作用域 | 触发条件 | 需要确认的内容 | 状态 |

常见需要约束的动作：

- 改变业务规则或数据语义；
- 删除源功能；
- 改变权限；
- 引入新依赖；
- 批量 Codemod；
- 修改 API contract；
- 执行高风险或不可逆操作。

## 新对话恢复

新的 Agent / 新对话开始迁移时：

1. 读取 `00-迁移状态总览.md`；
2. 读取本文件中所有“生效中”规则；
3. 与用户当前对话最新指令、Decision、目标仓库强制规则做冲突检查；
4. 根据当前 Module / Feature / Slice 筛选有效规则；
5. 在继续代码开发前确认没有违反“必须 / 禁止 / 必须询问”；
6. 不重复询问已经在规则或 Decision 中有明确答案的事项。
