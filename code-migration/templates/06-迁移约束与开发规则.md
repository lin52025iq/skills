# 迁移约束与开发规则

> 这是迁移过程中由用户、目标项目或已确认迁移决策定义的长期执行规则。规则可以约束工具、技术方案、代码组织、测试、操作方式和必须确认的行为。**长周期迁移中新对话必须先读取本文件。**

## 使用原则

1. 用户明确规则优先于 Agent 偏好；与目标项目强制规范冲突时必须显式指出并进入澄清；
2. 规则必须尽量写成可判断是否满足的形式；
3. 每条规则必须标明作用域、触发条件和强度；
4. `必须` 和 `禁止` 属于强约束；
5. `必须询问` 表示执行前需要用户确认；
6. `建议` 允许有证据地偏离，但要记录原因；
7. 规则变化要更新状态，不删除历史依据；
8. 不把一次性聊天偏好自动升级为永久规则；
9. 用户当前对话中的最新明确指令高于本文件中的旧规则。

## 规则强度

```

```

## 作用域

```text
全局 / 模块 / 功能 / 功能子项 / 切片 / 工作流
```

具体规则不能静默覆盖更高优先级的用户明确“必须 / 禁止”；强约束冲突时进入澄清。

### 指定工具不可用

当“必须”规则要求使用指定工具时，先确认工具是否存在、是否有权限、环境是否支持、是否能完成要求。

如果不可用：

```text
相关切片 / 功能子项 / 工作流 = 已阻塞
```

并记录：

- **阻塞原因**；
- **解除条件**；
- **不可用工具**；
- **可选替代方案**。

**不得静默改用替代工具。** 由用户决定启用工具、允许替代、修改规则或延后。

- 指定或禁止某个库、框架、状态方案；

- 指定某类代码必须采用的实现模式。

## 新对话恢复

新的 Agent / 新对话开始迁移时：

1. 读取 `00-迁移状态总览.md`；
2. 读取本文件所有“生效中”规则；
3. 与用户当前最新指令、迁移决策、目标仓库强制规则做冲突检查；
4. 根据当前模块 / 功能 / 切片 / 工作流筛选有效规则；
5. 开发前确认没有违反“必须 / 禁止 / 必须询问”；
6. 不重复询问已有明确答案的事项。
