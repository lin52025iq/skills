# 迁移模块功能点清单

> 这是迁移范围与完成度的权威台账。长期事实只维护 **Module / Feature / optional Group / Atomic Item**。临时 DEV/VER Batch 在 `05-迁移执行计划.md` 中记录，不进入本台账的长期状态模型。

## 层级模型

```text
模块
└─ 功能
   ├─ 功能项组 / 场景组（可选）
   │  ├─ 原子功能项
   │  └─ 原子功能项
   └─ 原子功能项
```

- **模块**：稳定业务边界或页面能力集合；
- **功能**：用户可独立描述的完整能力；
- **功能项组 / 场景组**：可选的阅读/聚合层；
- **原子功能项**：唯一细粒度实施/验证事实源。

## 原子性规则

原子功能项必须具备：

```text
一个主要产品/工程语义
+ 清晰触发 / 条件
+ 可观察或可证明的结果
+ 可判断实施完成
+ 可判断验证通过
```

需要拆分的信号：

- 不同点能独立遗漏或失败；
- 可以独立验证；
- 有不同权限 / Flag / 状态条件；
- 有不同错误、副作用、导航或交互结果；
- 用户可能单独保留 / 修改 / 删除其中一个点。

不要拆到 DOM、函数、变量、CSS class 或普通代码步骤。

## 来源类型

```text
源系统证据
用户明确新增
目标产品要求
目标项目强制约束
推断候选
未知
```

前四类可进入正式范围；`推断候选 / 未知` 不能静默成为 `范围内 + 必需=是`。

## 迁移决策与处理方式

迁移决策：

```text
保留 / 适配 / 合并 / 拆分 / 移除
替换 / 复用目标 / 新增 / 延后 / 未知
```

处理方式：

```text
新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
```

## 原子功能项状态

```text
当前状态：未开始 / 开发中 / 待验证 / 验证中 / 验证失败 / 已完成 / 已阻塞 / 已延后 / 不适用
范围状态：范围内 / 延后 / 范围外
实施状态：未开始 / 实施中 / 已实施 / 不适用
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
阻塞状态：未阻塞 / 已阻塞
是否必需：是 / 否
```

`验证状态=失败 → 当前状态=验证失败`；真实流程阻塞时才使用 `已阻塞`。

## 功能生命周期

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

功能只能由全部范围内必需原子项、要求的 Discovery / 07 / 08 验证和必要集成验证向上派生，不能由某一个原子项、Group 或 Batch 直接写成 `已迁移`。

## 模块状态

模块只维护派生摘要：

```text
未开始 / 进行中 / 验证中 / 已完成 / 已阻塞
```

不为 Module 再复制实施状态、验证状态、生命周期等完整状态维度。

- [ ] 所有范围内必需功能达到目标生命周期；
- [ ] 无必需功能未完成 / 验证失败 / 阻塞；
- [ ] 模块共享 Route / API / State / Permission / Layout / Style 的必要集成验证通过；
- [ ] 模块级用户目标和新方案成立。

### 原子性检查

- [ ] 每个原子项只有一个主要语义；
- [ ] 具有可观察或可证明的结果；
- [ ] 可独立判断实施与验证；
- [ ] 没有复合多个可独立失败点；
- [ ] 没有拆到无业务意义的实现细节；
- [ ] 只有确实提高可读性时才建立 Group。

### 来源真实性检查

- [ ] 每个正式原子项都有来源；
- [ ] `源系统证据` 可指向证据；
- [ ] `新增` 有用户 / 产品 / 强制约束 / Decision 依据；
- [ ] 推断候选 / 未知没有静默进入必需范围；
- [ ] 没有因 Target 存在组件而自动新增产品能力。

### 功能完成 Gate

- [ ] 全部范围内必需原子功能项为 `已完成`；
- [ ] 无必需原子项验证失败 / 阻塞；
- [ ] 要求的 Discovery 已达到可实施/完成标准；
- [ ] 要求的 07 / 08 验证通过；
- [ ] 必要集成验证通过；
- [ ] 功能生命周期已重新派生。

```text
Atomic Item 已完成 ≠ Group 已完成 ≠ Feature 已迁移 ≠ Module 已完成
```
