# 迁移模块功能点清单

> 这是迁移范围与完成度的功能级台账，独立于 Slice Queue。Slice Queue 负责“现在做什么”，本文件负责“完整有哪些模块、功能、子功能项，以及每一项做到什么程度”。开发过程中必须持续更新。

## 层级模型

```text
Module
  └─ Feature
       └─ Feature Item / 子功能项
```

- Module：业务或页面区域；
- Feature：可独立描述用户目标的能力；
- Feature Item：Feature 内需要实现或验证的具体细项；
- Source Behavior：源系统可观察行为，用于约束 Feature Item；
- Slice：执行调度单位；
- Workstream：由一个明确 Owner 负责的分析、实施或验证工作流；多个独立 Workstream 可以并行。

## 使用规则

1. 大规模开发前先完成 Module → Feature → Feature Item 盘点；
2. 每个 Feature / 重要 Item 使用稳定 ID；
3. 关键 Source Behavior 使用稳定 Behavior ID，并与 Feature Item 建立映射；
4. Slice Queue 不能替代本清单；
5. 开始开发 Item 时立即更新实施状态；
6. 只有所有“范围内 + 必需”的 Items 达标，Feature 才能“已迁移”；
7. 不迁移、延后、复用目标能力也保留并记录依据；
8. 并行开发时，每个实施中的 Feature / Item 必须记录 Workstream 与 Owner；
9. 同一个 Item 同一时刻只能有一个生产代码 Owner；
10. Workstream 输入基线变化时，受影响 Items 必须重新检查后再继续。

## 状态维度

### 范围状态

```text
范围内 / 延后 / 范围外
```

### 实施状态

```text
未开始 → 实施中 → 已实施
```

### 验证状态

```text
未验证 → 验证中 → 通过 / 失败 / 不适用
```

### 阻塞状态

```text
未阻塞 / 已阻塞
```

### 是否必需

```text
是 / 否
```

## Feature 生命周期

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

- 已发现：功能已识别，但目标行为或 Items 尚不完整；
- 已设计：必需 Items、Source Coverage、目标行为、Target Mapping 和验证方式已明确；
- 实施中：仍有必需 Item 未实施；
- 验证中：必需 Items 已实施，但仍有验证未通过/不适用；
- 已迁移：所有“范围内 + 必需=是”Items 已实施且验证通过/不适用，并且关键保持行为无遗漏；
- 已清理：目标能力完成且旧实现、入口和临时结构已安全退出。

## 开发时同步更新纪律

```text
选择 Workstream / Slice / Feature Items
→ 确认 Source Behavior / Target Behavior
→ 确认 Input Baseline / Ownership / Workspace Isolation
→ 确认并行安全
→ 实施状态 = 实施中
→ 开发
→ 实施状态 = 已实施
→ Item 级验证
→ 验证状态 = 通过 / 失败 / 不适用
→ 更新阻塞状态
→ 重新计算 Feature 生命周期
→ 更新 Workstream / Slice Queue
→ 必要时 Integration Gate
→ 长周期任务同步 00-迁移状态总览
```

如果开发中发现新的必要行为或子功能：立即加入 Source Behavior / Item 清单，更新目标决策，判断是否影响 Workstream Input Baseline，并重新检查开始条件。

如果实际代码状态与本清单冲突，以已确认 Decision、真实代码/Git/Runtime/Test 为依据，先重新校准清单再继续开发。
