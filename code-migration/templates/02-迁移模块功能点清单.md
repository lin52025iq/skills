# 迁移模块功能点清单

> 这是迁移范围与完成度的功能级台账，独立于执行队列。**本文件不仅记录“做到了哪一步”，还必须证明“这个功能点为什么存在”。**

## 层级模型

```text
模块
  └─ 功能
       └─ 功能子项
```

## 使用规则

1. 大规模开发前先完成 **模块 → 功能 → 功能子项** 盘点；
2. 每个功能 / 重要子项使用稳定 ID；
3. 每个正式功能 / 子项必须记录来源类型与来源依据；
4. 关键源行为使用稳定行为 ID，并与功能子项建立映射；
5. `02` 是 **功能范围、来源、处理方式、实施状态和当前状态的权威源**；
6. `07` 负责源行为决策 / 覆盖 / 验证，不复制实施事实；
7. `08` 负责复杂前端页面结构、交互语义和目标 UX / 布局验证；
8. 同一个子项同一时刻只能有一个生产代码负责人。

## 来源类型

```text
源系统证据
用户明确新增
目标产品要求
目标项目强制约束
推断候选
未知
```

**只有前四类可以直接进入正式范围。** `推断候选 / 未知` 不能静默成为 `范围内 + 必需=是`。

合法的新增依据至少包含一个：

```text
用户明确要求
已确认目标产品需求
目标仓库不可绕过的强制契约
已确认迁移决策记录
```

目标项目已有组件、行业惯例或 Agent 建议不能单独作为新增产品能力的依据。

## 迁移决策与处理方式

迁移决策：

```text
保留 / 适配 / 合并 / 拆分 / 移除
替换 / 复用目标 / 新增 / 延后 / 未知
```

处理方式：

```text
新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
```

## 状态维度

### 当前状态

```text
未开始 / 开发中 / 待验证 / 验证中 / 验证失败
已完成 / 已阻塞 / 已延后 / 不适用
```

推导规则：

1. `阻塞状态=已阻塞` → `已阻塞`；
2. `范围状态=延后` → `已延后`；
3. `范围状态=范围外` → `不适用`；
4. `验证状态=失败` → `验证失败`；
5. `实施状态=实施中` → `开发中`；
6. `新实现/修改现有 + 实施状态=未开始` → `未开始`；
7. `新实现/修改现有 + 已实施 + 未验证` → `待验证`；
8. `复用已有/无需实施 + 未验证` → `待验证`；
9. `验证状态=验证中` → `验证中`；
10. 要求的处理动作已满足且验证通过/不适用 → `已完成`。

### 详细状态

```text
范围状态：范围内 / 延后 / 范围外
处理方式：新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
实施状态：未开始 / 实施中 / 已实施 / 不适用
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
阻塞状态：未阻塞 / 已阻塞
是否必需：是 / 否
```

## 功能生命周期

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

- `已发现`：能力已识别，但范围 / 来源 / 目标行为尚不完整；
- `已设计`：来源真实性、必需子项、目标行为和要求的覆盖检查已明确；
- `实施中`：仍有需要实施的必需子项未完成；
- `验证中`：处理要求已满足，但必要验证尚未完成或失败；
- `已迁移`：所有范围内必需子项按处理方式完成，要求的发现 / 行为 / 交互 / 结构验证通过；
- `已清理`：旧实现、入口和临时结构已安全退出。

## 开发时同步更新纪律

```text
发现 / 选择功能子项
→ 检查来源真实性
→ 确认迁移决策 / 处理方式 / 风险级别
→ 必要时更新 07 / 08
→ 实施
→ 待验证 / 验证中
→ 通过：已完成
→ 失败：验证失败
→ 阻塞：已阻塞
→ 重新计算功能生命周期
```

开发中发现新能力时，**先作为候选登记并判断来源 / 范围，再决定是否实施**；不得“顺手”把设计建议变成正式功能。
