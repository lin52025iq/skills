# 迁移模块功能点清单

> 这是迁移范围与完成度的功能级台账，独立于执行队列。执行队列负责“现在做什么”，本文件负责“完整有哪些模块、功能、子功能项，以及每一项做到什么程度”。**开发过程中必须持续更新。**

## 层级模型

```text
模块
  └─ 功能
       └─ 功能子项
```

- **模块**：业务或页面区域；
- **功能**：可独立描述用户目标的能力；
- **功能子项**：功能内需要实现或验证的具体细项；
- **源行为**：源系统可观察行为，用于约束功能子项；
- **切片**：执行调度单位；
- **工作流**：由明确负责人负责的分析、实施或验证工作流。

## 使用规则

1. 大规模开发前先完成 **模块 → 功能 → 功能子项** 盘点；
2. 每个功能 / 重要子项使用稳定 ID；
3. 关键源行为使用稳定行为 ID，并与功能子项建立映射；
4. 执行队列不能替代本清单；
5. `02` 是 **功能子项实施状态的权威源**；
6. `07-源行为与目标对齐清单.md` 不重复维护实施事实，主要维护源行为决策、覆盖和验证；
7. 同一个子项同一时刻只能有一个生产代码负责人；
8. 工作流输入基线变化时，受影响子项必须重新检查后再继续。

## 迁移决策与处理方式

迁移决策：

```text
保留 / 适配 / 合并 / 拆分 / 移除
替换 / 复用目标 / 新增 / 延后 / 未知
```

处理方式：

```text
新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
```

**处理方式决定是否真的需要写代码。**

- `复用目标` 通常对应 `复用已有`，允许 `实施状态=不适用`，但必须验证；
- `移除` 通常对应 `移除已有`，必须确认移除动作及验证完成；
- `无需实施` 不得伪造成“已实施”；
- `未知` 通常对应 `待决定`。

## 状态维度

### **当前状态**

每个功能子项必须直接展示：

```text
未开始 / 开发中 / 待验证 / 验证中 / 验证失败
已完成 / 已阻塞 / 已延后 / 不适用
```

推导规则：

1. `阻塞状态=已阻塞` → `已阻塞`；
2. `范围状态=延后` → `已延后`；
3. `范围状态=范围外` → `不适用`；
4. `验证状态=失败` → `验证失败`；
5. `实施状态=实施中` → `开发中`；
6. `新实现/修改现有 + 实施状态=未开始` → `未开始`；
7. `新实现/修改现有 + 已实施 + 未验证` → `待验证`；
8. `复用已有/无需实施 + 未验证` → `待验证`；
9. `验证状态=验证中` → `验证中`；
10. 要求的实施动作已满足且验证通过/不适用 → `已完成`。

**不得让“当前状态”与详细状态或处理方式矛盾。**

### 详细状态

```text
范围状态：范围内 / 延后 / 范围外
处理方式：新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
实施状态：未开始 / 实施中 / 已实施 / 不适用
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
阻塞状态：未阻塞 / 已阻塞
是否必需：是 / 否
```

## 功能生命周期

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

- `已发现`：功能已识别，但目标行为或子项尚不完整；
- `已设计`：必需子项、目标行为、源行为覆盖和验证方式已明确；
- `实施中`：仍有需要实施的必需子项未完成；
- `验证中`：实施要求已满足，但仍有必要验证未完成或失败；
- `已迁移`：所有范围内必需子项按各自处理方式达到完成条件，源行为覆盖通过且必要验证通过；
- `已清理`：旧实现、入口和临时结构已安全退出。

> **功能子项“已完成”不自动等于整个功能“已迁移”。**

- [ ] 所有“保持”行为至少映射一个范围内功能子项；

- [ ] 权限 / 状态 / 错误 / 导航 / 数据契约等适用维度已覆盖；
- [ ] 不存在会改变当前实施方向的关键“未知”。

### 功能完成检查门槛

- [ ] 所有必需功能子项已识别；
- [ ] 要求的源行为覆盖检查已通过；
- [ ] 所有范围内必需子项按处理方式达到完成条件；
- [ ] 不存在验证失败或已阻塞的必需子项；
- [ ] 工作流输入基线无未处理漂移；
- [ ] 业务规则 / Invariant、权限、数据契约、错误路径已按风险验证；
- [ ] 必要集成验证已通过；
- [ ] 功能生命周期已重新计算。

## 开发时同步更新纪律

```text
选择功能子项
→ 确认迁移决策 / 处理方式 / 风险级别
→ 当前状态 = 开发中（如需要实施）
→ 更新 02 中实施状态
→ 实施动作完成或确认无需实施/复用已有
→ 当前状态 = 待验证
→ 验证中
→ 通过：已完成
→ 失败：验证失败
→ 阻塞：已阻塞
→ 重新计算功能生命周期
```

如果开发中发现新的必要行为或子功能，立即加入台账并重新评估风险级别、处理方式、输入基线和完成条件。

如果实际代码状态与本清单冲突，以已确认决策、真实代码 / Git / Runtime / 测试为依据，先重新校准清单再继续开发。
