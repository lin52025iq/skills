# 迁移模块功能点清单

> 这是迁移范围与完成度的功能级台账，独立于执行队列。执行队列负责“现在做什么”，本文件负责“完整有哪些模块、功能、子功能项，以及每一项做到什么程度”。**开发过程中必须持续更新。**

## 层级模型

```text
模块
  └─ 功能
       └─ 功能子项
```

- **模块**：业务或页面区域；
- **功能**：可独立描述用户目标的能力；
- **功能子项**：功能内需要实现或验证的具体细项；
- **源行为**：源系统可观察行为，用于约束功能子项；
- **切片（Slice）**：执行调度单位；
- **工作流（Workstream）**：由一个明确负责人负责的分析、实施或验证工作流；多个独立工作流可以并行。

## 使用规则

1. 大规模开发前先完成 **模块 → 功能 → 功能子项** 盘点；
2. 每个功能 / 重要子项使用稳定 ID；
3. 关键源行为使用稳定行为 ID，并与功能子项建立映射；
4. 执行队列不能替代本清单；
5. 开始开发子项时立即更新实施状态和当前状态；
6. 只有所有“范围内 + 必需”的子项达标，功能才允许进入“已迁移”；
7. 不迁移、延后、复用目标能力也保留并记录依据；
8. 并行开发时，每个实施中的功能 / 子项必须记录工作流与负责人；
9. 同一个子项同一时刻只能有一个生产代码负责人；
10. 工作流输入基线变化时，受影响子项必须重新检查后再继续；
11. **“当前状态”是面向人和调度 Agent 的汇总状态，必须与详细状态一致。**

## 迁移决策

功能的迁移决策统一使用中文：

```text
保留 / 适配 / 合并 / 拆分 / 移除
替换 / 复用目标 / 新增 / 延后 / 未知
```

- `保留`：目标继续保留能力和关键行为，实现方式可变化；
- `适配`：能力保留，但目标行为或实现按新要求调整；
- `合并`：多个来源融合成一个目标能力；
- `拆分`：一个源能力拆成多个目标能力；
- `移除`：目标明确不再需要；
- `替换`：由新的产品能力或实现取代；
- `复用目标`：目标项目已有能力可直接复用；
- `新增`：迁移范围内明确新增；
- `延后`：相关但当前阶段不处理；
- `未知`：证据不足，尚不能安全决策。

## 状态维度

### **当前状态**

每个功能和功能子项必须直接展示：

```text
未开始 / 开发中 / 待验证 / 验证中 / 已完成 / 已阻塞 / 已延后 / 不适用
```

当前状态从详细状态推导：

1. `阻塞状态=已阻塞` → `当前状态=已阻塞`；
2. `范围状态=延后` → `当前状态=已延后`；
3. `范围状态=范围外` 或明确无需实现 → `当前状态=不适用`；
4. `实施状态=未开始` → `当前状态=未开始`；
5. `实施状态=实施中` → `当前状态=开发中`；
6. `实施状态=已实施 + 验证状态=未验证` → `当前状态=待验证`；
7. `验证状态=验证中` → `当前状态=验证中`；
8. `实施状态=已实施 + 验证状态=通过/不适用` → `当前状态=已完成`。

**不得手工把“当前状态”写成与详细状态不一致的值。**

### 范围状态

```text
范围内 / 延后 / 范围外
```

### 实施状态

```text
未开始 → 实施中 → 已实施
```

### 验证状态

```text
未验证 → 验证中 → 通过 / 失败 / 不适用
```

### 阻塞状态

```text
未阻塞 / 已阻塞
```

### 是否必需

```text
是 / 否
```

## 功能生命周期

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

- `已发现`：功能已识别，但目标行为或子项尚不完整；
- `已设计`：必需子项、源行为覆盖、目标行为、目标落点和验证方式已明确；
- `实施中`：仍有必需子项未实施；
- `验证中`：必需子项已实施，但仍有验证未完成；
- `已迁移`：所有“范围内 + 必需=是”子项的当前状态均为“已完成”，且关键保持行为无遗漏；
- `已清理`：目标能力完成且旧实现、入口和临时结构已安全退出。

## 开发时同步更新纪律

```text
选择工作流 / 切片 / 功能子项
→ 确认源行为 / 目标行为
→ 确认迁移决策 / 输入基线 / 负责人 / 工作区隔离
→ 确认并行安全
→ 当前状态 = 开发中
→ 实施状态 = 实施中
→ 开发
→ 实施状态 = 已实施
→ 当前状态 = 待验证
→ 子项级验证
→ 验证状态 = 验证中 / 通过 / 失败 / 不适用
→ 同步当前状态
→ 更新阻塞状态
→ 重新计算功能生命周期
→ 更新工作流 / 执行队列
→ 必要时执行集成验证
→ 长周期任务同步 00-迁移状态总览
```

如果开发中发现新的必要行为或子功能：立即加入源行为 / 功能子项清单，更新迁移决策和当前状态，判断是否影响工作流输入基线，并重新检查开始条件。

如果实际代码状态与本清单冲突，以已确认决策、真实代码 / Git / Runtime / 测试为依据，先重新校准清单再继续开发。
