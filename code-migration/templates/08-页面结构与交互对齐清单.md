
### 交互时序

关键交互按以下结构记录：

```text
前置条件
→ 用户触发
→ 即时反馈
→ 中间状态
→ 数据操作
→ 成功结果 / 失败结果
→ 副作用
→ 交互收尾
```

示例：

```text
退款
→ 点击按钮
→ 打开 Drawer
→ 输入金额 / 原因
→ 提交时禁用按钮 + Loading
→ 成功：关闭 + Toast + 刷新订单/退款历史/Timeline
→ 409：保留输入，不关闭 Drawer，显示恢复提示
```

## 交互细节检查

按适用项检查：

- [ ] 显示 / 隐藏 / Disabled 条件；
- [ ] Page / Modal / Drawer / Popover / Inline 形态；
- [ ] Loading / Optimistic 状态；
- [ ] 重复提交 / 并发 / Cancel；
- [ ] debounce / throttle；
- [ ] 输入 / 草稿保留；
- [ ] 成功后的关闭 / Toast / 刷新 / 跳转；
- [ ] 失败后的错误定位 / Retry / 状态恢复；
- [ ] URL / Deep Link / Back / Forward；
- [ ] Focus / Tab / Enter / Esc / 快捷键；
- [ ] Scroll Lock / 滚动位置恢复。

## 交互不变量

- 

示例：

```text
提交中不能重复提交
409 后保留用户输入
未保存离开必须确认
关闭弹层后焦点回到触发元素
返回列表后保留筛选与分页
```

## 源视觉 / 交互证据

高风险页面优先使用运行证据：

```text
C3：实际运行页面 + 多 Viewport + 实际交互
C2：设计稿 / Storybook / 视觉测试 / 已有截图
C1：DOM / CSS / 组件结构 / Layout 代码
```

源系统可运行时，高风险页面不要只依据静态源码猜布局和交互。

## 结构与交互验证

### 结构验证

- [ ] 区域树符合目标期望结构；
- [ ] 关键区域顺序正确；
- [ ] 单栏 / 双栏 / Overlay 关系正确；
- [ ] 关键宽度比例和对齐正确；
- [ ] Scroll / Sticky / Fixed 正确；
- [ ] 响应式结构转换正确；
- [ ] 用户批准的新布局方案正确落地。

### 交互验证

- [ ] 关键触发条件正确；
- [ ] 即时反馈和中间状态正确；
- [ ] 成功 / 失败 / 恢复路径正确；
- [ ] 副作用完整；
- [ ] URL / Focus / Keyboard / Scroll 语义符合目标；
- [ ] 用户批准的新交互方案正确落地。

## 差异分类

```text
结构错误 / 交互错误 / 视觉错误
已批准结构变化 / 已批准交互变化
目标原生差异 / 环境噪声 / 未知
```

**用户已批准的新布局或交互方案不是回归，不得为了和 Source 一样而修回旧方案。**
