## Slice Queue 与功能台账

```text
功能台账
→ 选择 Feature Items
→ Source Coverage Gate
→ 形成 Slice / Workstream
→ 实施与验证
→ 更新 Feature Item
→ Workstream Validation
→ 必要时 Integration Gate
```

规则：

- Slice“已完成”不代表整个 Feature 自动“已迁移”；
- 不允许执行功能台账中不存在的工作；
- 新发现必要功能先补台账；
- Feature 是否完成由全部“范围内 + 必需=是”Items 决定。

## Source Coverage Gate

当前 Workstream / Slice 开始前：

- [ ] 关键 Source Behavior 已盘点
- [ ] 每条关键行为有稳定 ID
- [ ] 每条行为已有“保持 / 目标修改 / 不迁移 / 未知”决策
- [ ] 所有“保持”行为至少映射一个范围内 Feature Item
- [ ] 所有“目标修改”有明确 Desired Target Behavior
- [ ] 所有“不迁移”有依据
- [ ] 权限 / 状态 / 错误 / Loading / Empty / Navigation / Data Contract 等适用维度已覆盖
- [ ] 不存在会改变当前实施方向的关键“未知”

复杂 Feature 的详细映射见 `07-源行为与目标对齐清单.md` 或模块级同类文档。

## Parallel Safety Gate

新增并行实施 Workstream 前：

- [ ] 不会修改相同生产文件 / 组件
- [ ] 不会同时修改同一 Route / Layout / Store / Query ownership
- [ ] 不共享尚未稳定的 API / Data Contract / shared types
- [ ] 不同时修改同一权限模型 / 状态机 / Invariant
- [ ] 不依赖同一个未完成 Foundation
- [ ] 不同时修改同一公共组件 / abstraction
- [ ] 不同时修改同一 Adapter / Feature Flag / 切流路径
- [ ] 不同时修改 package manifest / lockfile
- [ ] 不同时修改 barrel / index / Route / Navigation / Permission registry
- [ ] 不同时写入 codegen / schema / generated types / i18n aggregate
- [ ] 共享脚本或生成器不会覆盖彼此输出
- [ ] 没有明确先后依赖
- [ ] 代码、数据/契约、业务语义、发布/合并路径均足够独立
- [ ] 共享 Contract / Foundation 已有唯一 Owner

有高风险重叠时：拆共享 Foundation、指定唯一 Owner，或退回串行。

## Workspace Isolation

并行 Implementer 优先使用：

```text
独立 branch / worktree / isolated workspace
```

如果共享 working tree：

- 必须记录允许修改范围；
- lockfile / generated / registry / aggregate 文件必须唯一 Owner；
- 同一迁移状态块同一时刻只能有一个 Writer；
- 无法可靠隔离时退回串行。

## Integration Gate

多个 Workstream 合并或进入共享运行边界后，执行：

- [ ] build
- [ ] typecheck / lint（适用时）
- [ ] shared unit / integration tests
- [ ] Route / Navigation / Permission registry
- [ ] shared state / query cache / API contract
- [ ] 关键 E2E / 用户路径
- [ ] CSS / Design System / bundle 等共享影响
- [ ] 用户生效规则
- [ ] 合并后没有新增 Feature Item 回归
- [ ] lockfile / generated / registry 结果一致

| Integration Batch | Workstreams | 结果 | 冲突 / 回归 | 修复 Owner | 重新验证 |
|---|---|---|---|---|---|
| INT-001 |  | `未验证 / 验证中 / 通过 / 失败` |  |  |  |

Integration Gate 失败时，相关 Workstream 不进入最终完成状态。

## 并行冲突处理

发现共享写入、契约冲突、Decision 互相影响、输入基线过期或合并测试互相破坏时：

1. 暂停受影响 Workstream；
2. 相关 Item 标记“已阻塞”；
3. Coordinator 重新划分 Ownership、拆 Foundation 或更新 Input Baseline；
4. 必要时退回串行；
5. 重新执行 Parallel Safety Gate；
6. 修复后重新执行 Workstream Validation / Integration Gate。

## 写入职责

- Implementer：当前 Workstream 生产代码 + 自己拥有的 Item 实施状态；
- Verifier：验证证据和验证状态；
- Analyst：Source / Target 分析输出；
- Coordinator：Active Workstreams、跨 Workstream 依赖/冲突、全局状态总览。

Coordinator 不承担所有细粒度状态更新，避免成为并行瓶颈。
