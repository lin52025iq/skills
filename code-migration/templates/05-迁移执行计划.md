## 风险治理强度

- **低风险**：功能台账 + 来源真实性 + 最小目标行为 + 最小必要验证；
- **中风险**：功能发现覆盖 + 关键源行为 + 复杂交互 / 页面结构检查 + 子项验证 + 必要输入基线；
- **高风险**：完整发现覆盖 + 源行为契约 + `08` 页面结构与交互契约 + C3 运行证据 + 独立验证 + 并行 / 集成治理。

风险升级时立即补齐更高等级要求。

## 执行链路

```text
功能台账
→ 检查来源真实性
→ 按风险执行功能发现覆盖
→ 源行为覆盖
→ 前端交互 / 页面结构覆盖（适用时）
→ 选择功能子项
→ 实施与即时验证
→ 工作流验证
→ 必要集成验证
```

**规则：**

- 切片“已完成”不代表整个功能自动“已迁移”；
- 新发现功能先作为候选写入台账，完成来源 / 范围判断后才能实施；
- 目标项目已有组件不能单独证明某个产品功能应该新增；
- 用户已批准的新交互 / 布局方案不能被 Source 对比“修回”旧方案。

如果运行环境不支持子 Agent 或隔离工作区，保留工作流模型但由当前 Agent 串行执行，**不得伪造并行能力**。

### 实施

根据处理方式执行：

```text
新实现 / 修改现有：实施状态 未开始 → 实施中 → 已实施
复用已有 / 无需实施：实施状态 = 不适用，直接进入验证
移除已有：记录移除动作，再进入验证
```

开发中发现新的功能点：

```text
先登记候选
→ 标记来源类型
→ 判断范围 / 必需性
→ 必要时补源行为 / 08
→ 再决定是否实施
```

禁止“顺手新增”。

### 子项级验证

```text
满足实施 / 处理要求
→ 待验证
→ 验证中
→ 通过 / 不适用：已完成
→ 失败：验证失败
→ 若真实阻塞后续：已阻塞
```

前端复杂功能验证同时按要求检查：功能行为、交互语义、页面结构、响应式和关键视觉层级。
