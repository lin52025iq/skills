## 并行安全检查

新增并行实施工作流前确认：

- [ ] 不会修改相同生产文件 / 组件；
- [ ] 不会同时修改同一路由 / 布局 / 状态 / 查询所有权；
- [ ] 不共享尚未稳定的 API / 数据契约 / 共享类型；
- [ ] 不同时修改同一权限模型 / 状态机 / Invariant；
- [ ] 不依赖同一个未完成公共基础；
- [ ] 不同时修改同一公共组件 / 抽象；
- [ ] 不同时修改同一 Adapter / Feature Flag / 切流路径；
- [ ] 不同时修改 package manifest / lockfile；
- [ ] 不同时修改 barrel / index / 路由 / 导航 / 权限注册表；
- [ ] 不同时写入 codegen / schema / generated / i18n 聚合文件；
- [ ] 共享脚本或生成器不会覆盖彼此输出；
- [ ] 没有明确先后依赖；
- [ ] 代码、数据/契约、业务语义、发布/合并路径均足够独立；
- [ ] 共享契约 / 公共基础已有唯一负责人。

有高风险重叠时：**拆共享基础、指定唯一负责人，或退回串行。**

## 工作区隔离

并行实施负责人优先使用：

```text
独立 branch / worktree / isolated workspace
```

如果共享 working tree：

- 必须记录允许修改范围；
- lockfile / generated / registry / aggregate 文件必须唯一负责人；
- 同一迁移状态块同一时刻只能有一个写入者；
- 无法可靠隔离时退回串行。

## 并行冲突处理

发现共享写入、契约冲突、迁移决策互相影响、输入基线过期或合并测试相互破坏时：

1. 暂停受影响工作流；
2. 相关子项标记“已阻塞”；
3. 协调负责人重新划分负责人、拆公共基础或更新输入基线；
4. 必要时退回串行；
5. 重新执行并行安全检查；
6. 修复后重新执行工作流验证 / 集成验证。

## 写入职责

- **实施负责人**：当前工作流生产代码 + 自己拥有的子项实施状态；
- **验证负责人**：验证证据和验证状态；
- **分析 Agent**：源 / 目标分析输出；
- **协调负责人**：活跃工作流、跨工作流依赖 / 冲突、全局状态总览。
