# 迁移执行计划

> 本文件只负责**工作流、临时执行批次和 Gate**。完整范围、原子功能项及其真实状态以 `02-迁移模块功能点清单.md` 为准。

## 执行模型

```text
Workstream
= 负责人 + 修改边界 + 并行/隔离边界

Batch
= 当前为了效率一起开发或一起验证的一组原子功能项

Atomic Item
= 唯一长期细粒度完成事实源
```

**不再维护独立 Slice 状态实体。** 如需描述“当前这一段工作”，直接使用 Workstream 当前 Batch。

Batch 是临时执行视图，不是迁移领域实体；无需建立独立生命周期或长期文档。

## 治理预算

### 低风险

```text
Feature + Atomic Item
+ 来源真实性
+ 最小验证
```

不强制功能项组、07、08、输入基线或独立验证负责人。

### 中风险

在低风险基础上按需增加：

```text
功能项组（仅为可读性）
关键 Discovery
关键 SB
关键 INT / REG
长任务输入基线
```

### 高风险

按需要启用完整：

```text
07 / 08
完整 Discovery
输入基线
独立验证
并行安全
集成验证
回滚 / 清理
```

**风险级别同时控制文档数量、ID 密度、Gate 数量和验证粒度，不只是控制是否创建 07/08。**

## Ready Gate

开始一个 Workstream / Batch 前按风险确认：

- [ ] 功能与原子功能项拆分合理；
- [ ] 原子项具有可观察或可证明的完成结果；
- [ ] 正式原子项都有合法来源；
- [ ] 要求的功能发现达到“足够进入实施”；
- [ ] 要求的源行为覆盖已完成；
- [ ] 复杂前端要求的交互 / 页面结构目标已明确；
- [ ] 用户新方案已进入目标；
- [ ] 验证方式明确；
- [ ] 用户规则、依赖、目标落点满足；
- [ ] 并行时负责人和工作区边界明确。

### Discovery 足够进入实施

不要求数学意义上的“绝对完整”。满足以下条件即可进入实施：

- 主要用户入口已覆盖；
- 关键 API / 状态 / Event 反向调用已检查；
- 关键权限 / Flag / 状态分支已分类；
- 相关测试已检查；
- 发现项都有来源和范围分类；
- 不存在会改变当前实现方向的关键未知。

## 活跃 Workstream

| Workstream | 模块 / 功能 | 风险 | 覆盖原子项 | 负责人 | 验证负责人 | 工作区边界 | 输入基线 | 状态 |
|---|---|---|---|---|---|---|---|---|
| WS-001 |  | `中风险` |  |  |  |  |  | `待执行 / 当前执行 / 已阻塞 / 验证中 / 已完成` |

同一原子功能项同时只能有一个生产代码负责人。

## 当前开发 Batch

仅在一次要一起开发多个强关联原子项时记录：

| Batch | Workstream | 原子功能项 | 共享实现上下文 | 状态 |
|---|---|---|---|---|
| DEV-001 | WS-001 |  |  | `待执行 / 开发中 / 已完成 / 已阻塞` |

开发结束后**逐原子项**更新实施状态。Batch 完成不改变功能生命周期。

简单任务不需要创建 DEV Batch；直接实施单个原子项即可。

## 当前验证 Batch

仅在多个原子项适合在同一真实用户场景下一起验证时记录：

| Batch | Workstream | 原子功能项 | 验证场景 | 结果 |
|---|---|---|---|---|
| VER-001 | WS-001 |  |  | `未验证 / 验证中 / 通过 / 失败` |

规则：

- 一次环境 / 数据准备可以覆盖多个原子项；
- 每个原子项仍有独立验证结果和证据；
- 单项失败不能被 Batch 通过覆盖；
- Batch 失败也不要求把已通过的其他原子项改成失败。

简单任务不需要创建 VER Batch；直接验证单个原子项即可。

## Workstream 完成条件

- [ ] 覆盖的原子功能项状态与真实代码一致；
- [ ] 临时 Batch 结果已经逐项回写；
- [ ] 要求的 07 / 08 验证结果已同步；
- [ ] 没有未处理的输入基线漂移；
- [ ] 功能项组状态已重新派生；
- [ ] 功能生命周期已重新派生；
- [ ] 必要集成验证已更新。

## 功能完成 Gate

功能只有在以下条件满足时进入 `已迁移`：

- 全部范围内必需原子功能项已完成；
- 无必需原子项验证失败或阻塞；
- 要求的 Discovery / 07 / 08 验证通过；
- 必要集成验证通过；
- 没有因局部完成而提前宣布整个功能完成。

## 模块完成 Gate

模块状态只做派生摘要。模块只有在：

- 所有范围内必需功能达到目标生命周期；
- 无必需功能未完成 / 验证失败 / 阻塞；
- 模块共享 Route / API / State / Permission / Layout / Style 的必要集成验证通过；
- 模块级用户目标和新方案成立；

之后才能标为 `已完成`。

```text
Batch 已完成 ≠ Workstream 已完成 ≠ Feature 已迁移 ≠ Module 已完成
```

## 并行与集成

Workstream 才是并行边界。并行前检查共享文件、Route/Layout/State/Query、API/契约、权限/状态机、公共基础、lockfile、registry/generated、全局样式和发布依赖。

环境不支持子 Agent / worktree / 安全隔离时，不伪造并行，保留 Workstream 模型并串行执行。

共享 Route/Layout、API/Query/State、权限、依赖/lockfile、Design System/全局样式、registry/generated 或同一发布批次时，执行必要集成验证。

## 交接

暂停或切换 Agent 前只记录长期有价值的信息：

- Workstream；
- 当前功能 / 原子功能项；
- 原子项真实实施 / 验证状态；
- 未完成和阻塞；
- 输入基线（如要求）；
- 当前临时 Batch（若尚未结束）；
- 下一安全动作。
