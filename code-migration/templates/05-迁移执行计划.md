## Slice Queue 与功能清单的关系

```text
02-迁移模块功能点清单
  定义完整 Module / Feature / Feature Item 范围和真实完成度
                    ↓
05-迁移执行计划
  从清单中选择下一批 Feature Items 组成 Slice 并调度执行
                    ↓
开发 / 验证
                    ↓
先更新 Feature Item 状态，再更新 Slice 状态
```

规则：

- Slice 可以覆盖一个完整 Feature，也可以只覆盖一个 Feature 的部分 Feature Items；
- 一个 Slice 标为 `DONE`，不代表整个 Feature 自动 `MIGRATED`；
- Slice 完成时必须逐项更新其覆盖的 Feature Items；
- Feature 是否完成，由功能点清单中的 Required Items 和 Feature Done Gate 决定；
- 不允许出现 Slice Queue 中执行了某项工作，但功能点清单没有对应 Feature/Item 的情况；发现新必要功能时先补清单再继续。

#### Implementation

- 

开发开始时，当前 Covered Feature Items 应立即更新为 `IMPLEMENTING`。

#### Validation

- 

主要代码完成开始验证时，对应 Feature Items 更新为 `VERIFYING`，并逐项写入验证结果。

#### Done Gate

- [ ] 本 Slice 覆盖的 Feature Items 均已更新真实状态

## 会话交接检查

结束当前开发会话、切换 Agent 或进入新对话前：

- [ ] 更新当前 Feature Items 的真实实施/验证状态
- [ ] 重新计算当前 Feature 生命周期，不把部分 Item 完成误标为 `MIGRATED`
- [ ] 更新模块功能点清单的汇总数量和当前焦点
- [ ] 更新 NOW / READY / BLOCKED / DEFERRED / DONE
- [ ] 写清最后完成的代码动作和验证结果
- [ ] 记录未完成但已经开始的 Item，避免下一对话重复实现
- [ ] 将新发现的业务规则、Target Behavior、Feature Item 或 Decision 写回对应文档
- [ ] 更新 `00-迁移状态总览.md` 的 Current Slice、Feature/Items、状态、最近完成、风险和 Recommended Next Action
- [ ] 如有未提交改动，明确文件范围和当前状态
- [ ] 如文档与代码状态不能确认一致，标记 `RECONCILE_REQUIRED`
