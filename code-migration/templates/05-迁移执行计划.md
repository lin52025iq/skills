## Slice Queue 与功能清单的关系

```text
02-迁移模块功能点清单
  定义完整 Module / Feature / Feature Item 范围和真实完成度
                    ↓
05-迁移执行计划
  从清单中选择下一批 Feature Items 组成 Slice 并调度执行
                    ↓
开发 / 验证
                    ↓
先更新 Feature Item 各状态维度，再更新 Slice 状态
```

规则：

- Slice 可以覆盖一个完整 Feature，也可以只覆盖一个 Feature 的部分 Feature Items；
- 一个 Slice 标为“已完成”，不代表整个 Feature 自动“已迁移”；
- Slice 完成时必须逐项更新 Covered Items 的范围状态、是否必需、实施状态、验证状态和阻塞状态；
- Feature 是否完成，由功能点清单中的“范围内 + 必需=是”Items 和 Feature Done Gate 决定；
- 不允许出现 Slice Queue 中执行了某项工作，但功能点清单没有对应 Feature/Item 的情况；发现新必要功能时先补清单再继续。

## 当前 Slice 适用规则

执行前从 `.code-migration/06-迁移约束与开发规则.md` 中筛选当前 Module / Feature / Feature Items / Slice 会触发的“生效中”规则。

| Rule ID | 作用域 | 触发条件 | 强度 | 当前要求 | 满足状态 | 证据 / 说明 |
|---|---|---|---|---|---|---|
|  |  |  | `必须 / 禁止 / 必须询问 / 建议` |  | `已满足 / 未满足 / 待确认 / 不触发` |  |

规则：

- 触发的“必须”未满足时，不得开始当前操作；
- 会违反“禁止”规则时必须修改方案；
- “必须询问”尚未确认时，相关 Slice/Item 标记“已阻塞”并向用户提问；
- 偏离“建议”时记录原因；
- 用户在开发过程中新增规则后，要重新检查当前 Slice 和待执行队列是否受影响。

#### 实施

- 

开发开始时，对应 Covered Items：

```text
实施状态 = 实施中
```

代码主体完成后：

```text
实施状态 = 已实施
```

不要把“代码写完”直接等同于 Item 完成。

#### 验证

- 

开始验证时：

```text
验证状态 = 验证中
```

验证结束后逐 Item 更新为：

```text
通过 / 失败 / 不适用
```

如果阻塞，必须同时写：

```text
阻塞状态 = 已阻塞
阻塞原因 = ...
解除条件 = ...
```
