## 执行原则

```text
范围拆分
→ 原子功能项
→ 功能项组 / 场景组
→ 开发批次
→ 一起实施
→ 逐原子项回写实施状态
→ 验证批次
→ 一起验证真实用户场景
→ 逐原子项回写验证结果
→ 汇总组 / 功能 / 模块
```

**拆分粒度和执行粒度必须分开。**

- 原子功能项是完成事实源；
- 功能项组用于组织强关联原子项；
- 开发批次用于一起开发；
- 验证批次用于一起验证；
- 批次、组、功能、模块的状态都不能覆盖单个原子项真实结果。

## 合理拆分 Gate

工作流开始前先检查 `02`：

- [ ] 功能按用户目标拆分，不按文件拆分；
- [ ] 复杂功能已按场景 / 能力形成必要功能项组；
- [ ] 每个原子功能项只有一个主要目标；
- [ ] 可以独立判断实施是否完成；
- [ ] 可以独立判断验证是否通过；
- [ ] 不存在“一条描述多个可独立失败点”的复合条目；
- [ ] 没有拆到 DOM / 函数 / 变量等过细粒度；
- [ ] 强关联项适合一起开发 / 验证时已建立批次。

如果原子性检查失败，**先重新拆分，再开发**。

## 功能发现与真实性 Gate

中/高风险默认执行：

- [ ] 用户入口、主要 / 次级操作已检查；
- [ ] 权限 / Role / Flag / 状态分支已检查；
- [ ] API / Mutation / 状态转换已反向查调用方；
- [ ] 自动行为 / 副作用 / Storage / Cache / URL / 测试已检查；
- [ ] 每个正式原子项都有合法来源；
- [ ] 推断候选 / 未知没有静默进入必需范围；
- [ ] 没有把目标项目已有组件误当成新增产品需求。

## 源行为 / 前端契约 Gate

按风险检查：

- 中/高风险：要求关键源行为覆盖；
- 复杂前端：要求交互语义和页面结构覆盖；
- 用户新 UX / 布局方案：必须进入目标交互 / 目标区域树；
- 要求的 `07 / 08` 验证方式必须在实施前明确。

## 开发批次

开发批次应尽量满足：

- 属于同一功能或紧密关联功能；
- 共享实现上下文；
- 修改范围清晰；
- 不因为一起开发而模糊原子项边界；
- 不包含尚未通过前置 Gate 的原子项。

| 开发批次 | 工作流 | 原子功能项 | 共享实现范围 | 开始条件 | 状态 |
|---|---|---|---|---|---|
| DEV-001 | WS-001 | F-001-I01,I02,I03 |  |  | `待执行 / 开发中 / 已完成 / 已阻塞` |

### 开发批次完成规则

批次可以标 `已完成`，但必须同时：

- [ ] 批次内每个原子项已经逐项更新实施状态；
- [ ] 未实施原子项没有被批次完成掩盖；
- [ ] 新发现原子项已登记并判断是否属于当前批次；
- [ ] 批次完成不修改功能生命周期为“已迁移”。

## 验证批次

验证批次可以把多个强关联原子项放到同一个真实用户场景中一起验证，例如：

```text
打开退款 Drawer
→ 校验金额
→ 提交
→ 验证重复提交保护
→ 构造 409
→ 验证输入恢复
→ 成功提交
→ 验证关闭 / Toast / 数据刷新
```

这样可以减少重复启动页面和重复准备数据，同时保留每个原子项的独立结论。

| 验证批次 | 工作流 | 原子功能项 | 验证场景 | 共享前置条件 | 批次结果 |
|---|---|---|---|---|---|
| VER-001 | WS-001 | F-001-I01,I02,I03 |  |  | `未验证 / 验证中 / 通过 / 失败` |

### 验证批次规则

1. 可以一次验证多个原子项；
2. 每个原子项仍写自己的 `验证状态` 和验证证据；
3. 某个原子项失败时，该项必须保持 `验证失败`；
4. 其他通过项可以保持 `已完成`；
5. 批次整体“通过”必须以全部要求验证的原子项通过 / 不适用为前提；
6. 批次失败不要求把所有原子项都标失败；
7. 验证场景发现新的遗漏点时，先补原子项，再重新计算功能完成度。

## 一起开发

```text
选择多个强关联原子项
→ 放入 DEV 批次
→ 一次完成共享上下文代码
→ 逐项判断处理要求是否满足
→ 逐项更新实施状态
```

禁止：

```text
DEV 批次代码“看起来完成”
→ 直接把所有原子项标已实施
```

## 一起验证

```text
选择共享用户场景的原子项
→ 放入 VER 批次
→ 一次准备环境 / 数据
→ 执行完整场景
→ 每个原子项分别记录验证结果
→ 再汇总批次结果
```

**允许一起验证，不允许一起糊成一个验证结论。**

## 功能项组汇总

功能项组状态完全派生：

- 任一必需原子项已阻塞 → 组 `已阻塞`；
- 任一必需原子项验证失败 → 组 `验证失败`；
- 存在开发中 → 组 `开发中`；
- 实施要求都满足但仍有未验证 → 组 `待验证 / 验证中`；
- 全部范围内必需原子项完成 → 组 `已完成`。

## 功能完成 Gate

功能只能进入 `已迁移`，当且仅当：

- [ ] 全部范围内必需原子项均为 `已完成`；
- [ ] 所有功能项组均无未完成必需原子项；
- [ ] 无验证失败 / 阻塞原子项；
- [ ] 要求的功能发现 / 源行为 / 交互 / 页面结构验证通过；
- [ ] 批量验证结果已逐项落账；
- [ ] 必要集成验证通过；
- [ ] 没有因完成局部功能而提前宣布整个功能完成。

## 模块完成 Gate

模块只能标记 `已完成`，当且仅当：

- [ ] 所有范围内必需功能达到 `已迁移 / 已清理` 中要求的目标状态；
- [ ] 不存在尚未完成、验证失败或阻塞的必需功能；
- [ ] 模块共享路由 / API / 状态 / 权限 / 样式的必要集成验证通过；
- [ ] 模块目标与用户新方案整体成立；
- [ ] 模块状态由功能汇总，而不是由最后一个开发批次决定。

## 并行安全

并行开发批次仍必须检查：共享文件、路由/布局/状态/查询所有权、API/数据契约、权限/状态机、公共基础、lockfile、注册表、生成文件和共享脚本。

运行环境不支持子 Agent 或安全隔离时，保留批次 / 工作流模型但串行执行。
