## Slice Queue 与功能台账

```text
02-迁移模块功能点清单
  定义完整 Module / Feature / Feature Item 范围和真实完成度
                    ↓
05-迁移执行计划
  选择 Feature Items 组成 Slice / Workstream 并调度执行
                    ↓
开发 / 验证
                    ↓
先更新 Feature Item 状态，再更新 Slice / Workstream 状态
```

规则：

- Slice 可以覆盖完整 Feature，也可以覆盖一组强关联 Feature Items；
- Slice“已完成”不代表 Feature 自动“已迁移”；
- Feature 是否完成，由所有“范围内 + 必需=是”Items 和 Feature Done Gate 决定；
- 不允许执行队列里存在功能台账中没有对应 Feature/Item 的工作；
- 新发现必要功能时先补台账再继续。

### 并行安全检查

新增实施 Workstream 前检查：

- [ ] 不会与其他实施 Workstream 修改相同生产文件/组件
- [ ] 不会同时修改同一 Route / Layout / Store / Query ownership
- [ ] 不共享尚未稳定的 API / Data Contract
- [ ] 不同时修改同一权限模型、状态机或业务 Invariant
- [ ] 不依赖同一个尚未完成的 Foundation
- [ ] 不同时修改同一公共组件 / abstraction
- [ ] 不同时修改同一 Adapter / Feature Flag / 切流路径
- [ ] 没有明确先后依赖
- [ ] 每个共享契约都有唯一 Owner

若任何一项存在高风险重叠：拆共享 Foundation、指定唯一 Owner，或退回串行实施。

同一个 Feature Item 同一时刻只能有一个生产代码 Owner。

## 当前 Slice 适用规则

执行前从 `.code-migration/06-迁移约束与开发规则.md` 筛选当前 Module / Feature / Feature Items / Slice 会触发的“生效中”规则。

| Rule ID | 作用域 | 触发条件 | 强度 | 当前要求 | 满足状态 | 证据 / 说明 |
|---|---|---|---|---|---|---|
|  |  |  | `必须 / 禁止 / 必须询问 / 建议` |  | `已满足 / 未满足 / 待确认 / 不触发` |  |

规则：

- “必须”未满足 → 不得开始；
- 会违反“禁止” → 修改方案；
- “必须询问”尚未确认 → 相关 Slice/Item 标记“已阻塞”；
- 偏离“建议” → 记录原因；
- 用户新增规则后，重新检查当前 Workstream 和待执行队列。

## 并行冲突处理

并行过程中发现共享写入、契约冲突、公共 abstraction 冲突、Decision 互相影响或合并测试相互破坏时：

1. 暂停受影响 Workstream；
2. 相关 Item 标记“已阻塞”；
3. Coordinator 重新划分 Ownership 或拆出共享 Foundation；
4. 必要时退回串行；
5. 冲突解决后重新执行并行安全检查。

不要为了保持并行度而继续制造冲突。
