## 风险治理强度

- **低风险**：功能台账 + 最小目标行为 + 最小必要验证即可；不强制独立源行为清单、输入基线和工作流验证；
- **中风险**：关键源行为覆盖、子项验证、必要输入基线；
- **高风险**：完整源行为契约、输入基线、独立验证、并行安全、工作区隔离、工作流验证和必要集成验证。

风险升级时立即补齐更高等级要求。

## 执行队列与功能台账

```text
功能台账
→ 按风险选择治理强度
→ 选择功能子项
→ 必要的源行为覆盖检查
→ 形成切片 / 工作流
→ 实施与验证
→ 更新功能子项
→ 必要的工作流验证
→ 强制条件命中时集成验证
```

**规则：**

- 切片“已完成”不代表整个功能自动“已迁移”；
- 新发现必要功能先补台账；
- 功能是否完成由全部范围内必需子项按各自处理方式的完成条件决定。

## 源行为覆盖检查

中/高风险默认执行；低风险按需：

- [ ] 关键源行为已盘点并有稳定 ID；
- [ ] 每条行为已有“保持 / 目标修改 / 不迁移 / 未知”决策；
- [ ] 所有“保持”行为至少映射一个范围内功能子项；
- [ ] 所有“目标修改”有明确目标期望行为；
- [ ] 权限 / 状态 / 错误 / 导航 / 数据契约等适用维度已覆盖；
- [ ] 不存在会改变实施方向的关键“未知”。

## 并行安全检查

并行实施前确认代码、数据/契约、业务语义和发布/合并路径足够独立，并检查：共享文件、路由/布局/状态/查询所有权、API/数据契约、权限/状态机、公共基础、lockfile、注册表、生成文件和共享脚本。

有高风险重叠时：**拆共享基础、指定唯一负责人，或退回串行。**

如果运行环境不支持子 Agent 或隔离工作区，保留工作流模型但由当前 Agent 串行执行，**不得伪造并行能力**。

### 实施

根据处理方式执行：

```text
新实现 / 修改现有：实施状态 未开始 → 实施中 → 已实施
复用已有 / 无需实施：实施状态 = 不适用，直接进入验证
移除已有：记录移除动作完成情况，再进入验证
```

### 子项级验证

```text
满足实施/处理要求
→ 当前状态 = 待验证
→ 验证状态 = 验证中
→ 当前状态 = 验证中
→ 通过/不适用：当前状态 = 已完成
→ 失败：当前状态 = 验证失败
→ 若失败阻塞后续：当前状态 = 已阻塞
```

## 集成验证

以下任一情况存在时，合并后 **强制执行集成验证**：

- 共享路由 / 布局；
- 共享 API / 查询 / 状态；
- 共享权限模型；
- 共享依赖 / lockfile；
- 共享设计系统 / 全局样式；
- 共享注册表 / codegen / generated 文件；
- 同一发布或切流批次。
