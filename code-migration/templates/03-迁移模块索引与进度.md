# 03 迁移模块索引与进度

> 顶层模块导航、派生进度和小模块权威事实。已经拆入 `modules/<模块目录>/` 的模块，其详细功能、原子功能项和实施状态以模块 `01-模块功能点.md` 为准；尚未达到独立维护规模的小模块可以继续在本文件内联维护。

## 核心原则

```text
独立模块：
模块 01 = 详细权威事实
顶层 03 = 模块索引 + 派生摘要 + 链接

内联小模块：
顶层 03 = 该模块的详细权威事实

公共业务能力：
modules/shared/01-公共功能点.md = 公共功能权威事实
```

同一功能点只能有一个详细权威位置。目录变化只改变承载位置，不改变模块、功能和原子功能项编号。

## 中文字段与状态约束


## Checkbox 规则

Checkbox 只是完成投影，不是状态输入。

```text
原子功能项当前状态 = 已完成       → [x]
功能生命周期 = 已迁移 / 已清理     → [x]
模块派生状态 = 已完成               → [x]
其他状态                            → [ ]
```

若 Checkbox 与真实状态冲突，以权威事实中的真实状态为准并修正 Checkbox。

## 何时升级为独立模块

模块达到一定体量后，将详细事实从顶层 `03` 迁入独立目录。以下情况任一成立时优先升级：

- 有多个需要独立追踪的功能，顶层平铺明显降低可读性；
- 需要跨会话持续推进；
- 需要独立工作流或并行边界；
- 需要自己的功能语义、源行为或页面结构/交互契约；
- 风险较高，需要独立验证或集成结论；
- 多人或多个 Agent 会持续修改该模块；
- 顶层 `03` 中该模块已经明显影响其他模块浏览。

升级规则：

```text
M-008 通知设置（顶层内联）
↓ 只迁移承载位置
modules/M-008-通知设置/
├── 00-模块总览.md
└── 01-模块功能点.md
```

升级时必须保持原有 `模块编号 / 功能编号 / 原子功能项编号` 不变；`09`、决策记录、验证证据和其他引用只更新路径，不重新编号或重建语义。迁移完成后，顶层 `03` 删除该模块的详细原子功能项，只保留派生摘要和模块入口链接。

## 公共模块

`modules/shared/` 用于跨多个业务模块复用、具有独立业务或用户可观察语义、并且可以独立实施和验证的公共能力。

适合进入公共模块：权限校验、公共错误恢复、登录态恢复、跨模块通知、公共审计等业务能力。

不应进入公共模块：普通按钮、弹窗组件、日期格式化、通用 Hook、CSS 工具等纯工程基础设施。

业务模块引用公共功能编号，不复制公共功能的详细状态。

## 独立模块目录标准

```text
modules/M-xxx-模块名称/
├── 00-模块总览.md
├── 01-模块功能点.md
├── 02-功能语义.md              # 按需
├── 03-源行为对齐.md            # 按需
└── 04-页面结构与交互.md        # 按需

modules/shared/
├── 00-公共模块总览.md
└── 01-公共功能点.md
```

顶层 `04 / 05 / 06` 只保存真正的全局或跨模块契约；模块私有事实优先放模块目录。公共模块保存的是公共业务功能，不替代顶层全局契约。

## 模块完成检查门

模块只有在以下条件同时满足时才能派生为 `已完成`：

- [ ] 所有范围内必需功能达到目标生命周期；
- [ ] 不存在必需功能验证失败或阻塞；
- [ ] 必要公共功能依赖已满足；
- [ ] 模块共享边界的必要集成验证通过；
- [ ] 模块级用户目标与已确认新方案成立；
- [ ] 顶层摘要与详细权威事实一致。

## 导航要求

独立模块必须创建真实双向链接：

```text
顶层 03 → modules/M-xxx-模块名称/00-模块总览.md
模块 00 → ../../00-迁移状态总览.md
模块 00 → ../../03-迁移模块索引与进度.md
模块 00 → 01-模块功能点.md
模块 00 → 实际存在的 02/03/04
```

死链接、旧路径和拆分后仍保留两份详细事实都属于工作区一致性问题。
