## 状态规则

每条源行为/子项必须直接显示 **当前状态**：

```text
未开始 / 开发中 / 待验证 / 验证中 / 已完成 / 已阻塞 / 已延后 / 不适用
```

同时保留详细状态：

```text
实施状态：未开始 / 实施中 / 已实施
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
阻塞状态：未阻塞 / 已阻塞
```

**当前状态必须由详细状态推导，不得互相矛盾：**

1. `阻塞状态=已阻塞` → `当前状态=已阻塞`；
2. `目标决策=不迁移` → `当前状态=不适用`；
3. 明确延后处理 → `当前状态=已延后`；
4. `实施状态=未开始` → `当前状态=未开始`；
5. `实施状态=实施中` → `当前状态=开发中`；
6. `实施状态=已实施 + 验证状态=未验证` → `当前状态=待验证`；
7. `验证状态=验证中` → `当前状态=验证中`；
8. `实施状态=已实施 + 验证状态=通过/不适用` → `当前状态=已完成`。

- [ ] 关键源行为已盘点；
- [ ] 每条关键行为有稳定行为 ID；

## 开发时同步更新

```text
开始实现对应行为
→ 当前状态 = 开发中
→ 实施状态 = 实施中
→ 代码完成
→ 实施状态 = 已实施
→ 当前状态 = 待验证
→ 开始验证
→ 验证状态 = 验证中
→ 当前状态 = 验证中
→ 验证通过/不适用
→ 当前状态 = 已完成
```

验证失败时保留真实验证状态；如果失败会阻塞后续开发，同时设置 **阻塞状态=已阻塞、当前状态=已阻塞**。
