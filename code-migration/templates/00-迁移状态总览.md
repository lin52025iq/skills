规则：

- `MUST_ASK`：现有证据不足，且答案会实质改变产品行为、关键业务规则、权限/数据语义、范围取舍或不可安全推断的不可逆方向；

- 普通命名、目录、组件选择、已有成熟工程范例不默认询问用户；

- 用户回答后同步相关 Feature、Decision 和 Ready Gate；

## 事实源优先级

冲突时按以下顺序核对：

1. 用户最近一次明确且仍有效的迁移意图；
2. 已确认 Decision / 目标产品契约；
3. 当前真实代码、Git、Runtime 和测试结果；
4. 当前模块功能清单和执行计划；
5. 本状态总览。

不要拿过期的状态总览覆盖真实代码或已确认 Decision。高优先级来源之间冲突时进入 Reconcile / Clarification。

## 新对话恢复步骤

1. 先读取本文件，不要直接重新扫描所有源项目；
2. 恢复 Overall Goal、Desired Target Behavior、Current Slice、Decision、Invariant 和已回答问题；
3. 根据索引读取当前模块的功能清单与执行计划；
4. 检查 Git branch、最近相关 commit、working tree 和当前 Slice 实际代码；
5. 若状态一致，从 Recommended Next Action 续接；
6. 若不一致，只对当前相关范围 Reconcile，并更新状态后再写新代码；
7. 不重复开发 `MIGRATED/DONE` 项，不重复询问已有答案。

更详细的交接、Reconcile、版本控制、敏感信息和多 Agent 协作规则由 `$code-migration` Skill 的“迁移状态与跨会话协作”规范提供；运行时文档不依赖 Skill 安装目录的相对路径。
