## 事实源优先级

1. 用户最近一次明确且仍有效的迁移意图与开发约束；
2. 仍生效的用户规则和已确认 Decision / 目标产品契约；
3. 当前真实代码、Git、Runtime 和测试结果；
4. Source Behavior / 功能台账 / 执行计划；
5. 本状态总览。

## 新对话恢复步骤

1. 先读取本文件；
2. 恢复总体目标、执行模式、Active Workstreams、Owner、Input Baseline 和 Integration 状态；
3. 读取 `06-迁移约束与开发规则.md`；
4. 读取 `02-迁移模块功能点清单.md`，确认 Feature / Items、Source Behavior IDs、状态和 Ownership；
5. 读取 `07-源行为与目标对齐清单.md` 或当前模块行为文档，确认 Source Coverage；
6. 读取 `05-迁移执行计划.md`，确认 Workstream 依赖、Workspace Isolation 和下一动作；
7. 检查 Git、最近相关 commit、working tree 和活跃 Workstream 实际代码；
8. 检查 Input Baseline 是否仍有效；
9. 状态一致且规则/Source Coverage/并行安全检查通过时，从各 Workstream 下一动作续接；
10. 不一致时只对受影响范围重新校准；
11. 不重复开发“已迁移 / 已清理”项，不忽略生效规则、Ownership 或 Integration Gate。
