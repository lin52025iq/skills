# 09 迁移执行计划

> 本文件只负责 **Workstream、临时执行 Batch 和 Gate**。不复制模块详细范围。模块化后，Atomic Item 的真实状态读取 `modules/<module>/01-模块功能点.md`；未模块化的小模块才读取顶层 `03-迁移模块索引与进度.md` 中的局部事实。

## 执行模型

```text
Workstream = 负责人 + 修改边界 + 并行/隔离边界
Batch = 当前为了效率一起开发或验证的一组 Atomic Item
Atomic Item = 唯一长期细粒度完成事实源
```

不维护独立 Slice 状态实体。Batch 是临时执行视图，不建立长期生命周期。

## Atomic Item 引用规则

Workstream / Batch 只引用 Atomic Item ID 和其权威文件，不在本文件复制完整状态表。

```text
M-ORDER / F-REFUND-I03
→ modules/order/01-模块功能点.md#f-refund-i03-...
```

状态变化先写回模块 `01`，再更新 Batch / Workstream 汇总和 Checkbox 投影。

## Ready Gate

开始 Workstream / Batch 前按风险确认：

- [ ] 当前 Module 的权威功能文件已确定；
- [ ] Atomic Item 拆分合理且可验证；
- [ ] 正式 Atomic Item 有合法来源；
- [ ] 要求的 Discovery 足够进入实施；
- [ ] 模块私有 WHAT / HOW-WHERE 契约或顶层共享契约已明确；
- [ ] 用户新方案已进入 Target；
- [ ] `02` 生效规则已检查；
- [ ] 验证方式、依赖、目标落点满足；
- [ ] 并行时负责人和工作区边界明确；
- [ ] 顶层 `03` ↔ 模块 `00` 的导航有效。

## 功能与模块完成

```text
Atomic Item 真实状态
→ Feature 生命周期
→ Module 派生状态
→ 模块 00 Checklist
→ 顶层 03 Module Checklist
→ 00 全局摘要
```

任何上层 `[x]` 都不能先于下层真实状态更新。

## 并行与集成

Workstream 才是并行边界。并行前检查共享文件、Route/Layout/State/Query、API/契约、权限/状态机、公共基础、lockfile、registry/generated、全局样式和发布依赖。

环境不支持子 Agent / worktree / 安全隔离时，不伪造并行，保留 Workstream 模型并串行执行。

共享 Route/Layout、API/Query/State、权限、依赖/lockfile、Design System/全局样式、registry/generated 或同一发布批次时执行必要集成验证。

## 交接

暂停或切换 Agent 前记录：当前 Module 入口、Workstream、Feature / Atomic Item ID、权威模块文件、真实实施/验证状态、未完成和阻塞、尚未结束的临时 Batch、输入基线和下一安全动作。
