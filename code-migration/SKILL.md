---
name: code-migration
description: 用于将一个或多个现有项目中的功能、业务规则和用户能力迁移、融合或重构到目标项目。适用于前端项目迁入新仓库、跨框架或技术栈重实现、多项目能力融合、模块整合、功能删改融合、目标架构适配与渐进切流。迁移以真实源证据、功能发现真实性、目标期望行为、交互语义、页面结构和目标项目原生架构为中心；默认不按源文件、目录、组件或状态结构一比一翻译，并支持按风险治理、跨会话恢复和受控多 Agent 并行。
---

# Code Migration

把代码迁移视为 **“业务能力在新上下文中的受控重建”**，不是文件搬运或旧架构复制。

```text
源证据
→ 功能发现覆盖 + 来源真实性
→ 源行为契约
→ 交互语义 / 页面结构契约（前端适用时）
→ 用户新迁移方案 + 目标产品要求
→ 目标原生设计
→ 功能台账 / 工作流实施
→ 功能 + 行为 + 交互 + 结构验证
→ 集成 / 切流 / 清理
```

## 1. 核心原则

1. **迁移的是能力，不是文件。** 源文件只是证据，不是迁移边界。
2. **源项目是事实，不是目标规范。** Source 说明旧系统真实做了什么。
3. **发现完整性与发现真实性同等重要。** 既要防止漏功能，也要防止脑补不存在的功能。
4. **每个正式功能 / 子项必须有来源依据。** 没有来源证明不能静默进入必需迁移范围。
5. **关键源行为必须可追踪。** 每条关键行为决定“保持 / 目标修改 / 不迁移 / 未知”。
6. **交互语义必须显式。** 不能把“点击按钮”简化成“调用 API”。
7. **页面结构必须显式。** 前端复杂页面不能只验证元素存在，还要验证区域关系、响应式和空间结构。
8. **用户的新迁移方案决定目标变化。** 已确认的新 UX / 布局 / 交互方案优先于 Source 旧形态。
9. **目标项目决定实现形状。** 路由、状态、数据层、组件、Design System、目录、错误和测试遵循目标仓库稳定惯例。
10. **治理强度按风险自适应。** 低风险不机械承担高风险任务的完整流程。
11. **状态实时更新。** 功能子项、源行为和工作流不得靠事后补文档。
12. **迁移完成还包括验证、集成、切流和遗留清理。**

## 2. 工作区

已有 `.code-migration/` 时优先恢复：

1. `00-迁移状态总览.md`；
2. 用户新方案、生效规则、活跃工作流、输入基线；
3. `02-迁移模块功能点清单.md`；
4. 中/高风险的 `07-源行为与目标对齐清单.md`；
5. 复杂前端页面的 `08-页面结构与交互对齐清单.md`；
6. 执行计划、Git、代码和测试。

不一致时只对受影响范围重新校准。

长周期迁移按需创建：

```text
.code-migration/
├── 00-迁移状态总览.md
├── 01-迁移任务上下文.md
├── 02-迁移模块功能点清单.md
├── 03-功能融合映射.md
├── 04-迁移决策记录.md
├── 05-迁移执行计划.md
├── 06-迁移约束与开发规则.md
├── 07-源行为与目标对齐清单.md
├── 08-页面结构与交互对齐清单.md
└── modules/<module>/
```

小任务不机械创建全部文档。

## 3. 功能发现覆盖

中/高风险功能不只从 UI 往下追，要同时做：

```text
正向追踪：入口 → 行为 → 状态/数据 → API → 副作用 → 用户结果
反向追踪：API/Mutation/状态转换/Event → 调用方 → 条件/权限/Flag → 用户场景
```

至少检查适用项：

- 用户入口、路由、导航、深链接；
- 主要操作和次级操作；
- 权限 / Role；
- 状态机 / 枚举 / 类型分支；
- Feature Flag / 配置分支；
- API / Mutation / 状态转换调用方；
- 自动刷新、轮询、WebSocket / Event；
- Cache / Storage；
- Loading / Empty / Error / Recovery；
- URL / Back / 页面状态恢复；
- 相关测试中的隐含规则；
- 后台副作用和跨模块联动。

中/高风险功能形成轻量**功能触点图**，直到继续检查入口、反向调用、测试和分支时，不再持续出现新的关键必需能力，即“功能发现趋于稳定”。

## 4. 功能来源真实性

每个正式功能 / 子项记录来源类型：

```text
源系统证据
用户明确新增
目标产品要求
目标项目强制约束
推断候选
未知
```

规则：

- `源系统证据`：必须能指向 C3/C2/C1 证据；
- `用户明确新增`：可以形成“新增”目标能力；
- `目标产品要求`：按目标产品决定新增 / 适配 / 替换；
- `目标项目强制约束`：只加入实现不可绕过的要求；
- `推断候选 / 未知`：不能静默进入 `范围内 + 必需=是`。

以下不能单独作为正式新增依据：

```text
“一般后台都有”
“这样体验更好”
“目标项目其他页面有”
“目标项目有现成组件”
“Agent 建议”
```

**目标仓库已有能力只能说明“如果需要该能力应该如何实现”，不能决定产品范围。**

任何 `迁移决策=新增` 至少需要：用户明确要求、已确认目标产品需求、不可绕过的目标强制契约或已确认 Decision 之一。

## 5. 迁移决策与处理方式

功能迁移决策：

```text
保留 / 适配 / 合并 / 拆分 / 移除
替换 / 复用目标 / 新增 / 延后 / 未知
```

处理方式：

```text
新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
```

`复用目标 / 无需实施` 允许不产生新代码，但必须验证；不得伪造“已实施”。

源行为决策：

```text
保持 / 目标修改 / 不迁移 / 未知
```

重大产品变化、删除、融合、替换或 Invariant 变化记录 Decision。

## 6. 当前状态

功能子项 / 源行为适用状态：

```text
未开始 / 开发中 / 待验证 / 验证中 / 验证失败
已完成 / 已阻塞 / 已延后 / 不适用
```

详细状态：

```text
范围状态：范围内 / 延后 / 范围外
处理方式：新实现 / 修改现有 / 复用已有 / 移除已有 / 无需实施 / 待决定
实施状态：未开始 / 实施中 / 已实施 / 不适用
验证状态：未验证 / 验证中 / 通过 / 失败 / 不适用
阻塞状态：未阻塞 / 已阻塞
是否必需：是 / 否
```

`验证状态=失败 → 当前状态=验证失败`；只有真实阻塞时才变为 `已阻塞`。

功能层使用生命周期：

```text
已发现 → 已设计 → 实施中 → 验证中 → 已迁移 → 已清理
```

**子项已完成 ≠ 功能已迁移。**

## 7. 风险治理

### 低风险

- 功能台账；
- 来源真实性；
- 关键目标行为；
- 最小必要验证。

不强制完整 `07 / 08`、输入基线或多 Agent 编排。

### 中风险

增加：

- 功能发现覆盖；
- 关键源行为和覆盖；
- 复杂交互语义；
- 前端主要页面区域树 / 响应式结构；
- 子项级验证；
- 长任务输入基线。

### 高风险

增加完整治理：

- 完整功能触点与反向追踪；
- 完整源行为契约；
- 复杂前端页面 `08`；
- 源系统可运行时优先 C3 页面 / 交互证据；
- 独立验证；
- 并行安全 / 工作区隔离；
- 工作流验证 / 必要集成验证；
- 回滚和清理条件。

风险升级时立即补齐更高等级要求。

## 8. 源行为契约

证据等级：

```text
C3 运行证据
C2 契约 / 设计 / 视觉测试证据
C1 静态代码证据
C0 未知
```

关键源行为记录：

```text
源行为
证据
目标决策
目标期望行为
关联功能子项
验证方式
```

`02` 是功能范围、来源、处理方式、实施状态和当前状态的权威源；`07` 维护源行为决策、覆盖、目标实际表现、验证状态和验证证据。

## 9. 交互语义契约

复杂交互不能只写“点击 → API”。至少恢复：

```text
前置条件
→ 触发方式
→ 即时反馈
→ 中间状态
→ 数据操作
→ 成功结果 / 失败结果
→ 副作用
→ 交互收尾
```

按适用项检查：

- 显示 / 隐藏 / Disabled 条件；
- Page / Modal / Drawer / Popover / Inline；
- Loading / Optimistic；
- 重复提交 / 并发 / Cancel / debounce / throttle；
- 输入和草稿保留；
- 成功后的 Toast / 关闭 / 刷新 / 跳转；
- 失败后的 Retry / 状态恢复 / 输入保留；
- URL / Deep Link / Back / Forward；
- Focus / Tab / Enter / Esc / 快捷键；
- Scroll Lock / 滚动恢复。

交互决策：

```text
保持交互 / 目标适配 / 按新方案重构
合并交互 / 拆分交互 / 移除交互
新增交互 / 复用目标交互 / 未知
```

用户批准的新交互方案验证新方案，不修回 Source 旧交互。

## 10. 页面结构与视觉迁移契约

中/高风险复杂前端页面按需使用 `08-页面结构与交互对齐清单.md`。

先恢复用户感知的**页面区域树**，不是 DOM / Component Tree：

```text
PAGE
├─ HEADER
├─ MAIN
│  ├─ LEFT_COLUMN
│  └─ RIGHT_COLUMN
└─ TIMELINE
```

每个重要区域记录：父区域、排列、宽度/比例、高度、对齐、Gap/Padding 层级、Scroll Owner、Sticky/Fixed、显隐和响应式变化。

结构决策：

```text
保持结构 / 目标适配 / 按新方案重构
合并区域 / 拆分区域 / 移除区域
新增区域 / 复用目标结构 / 未知
```

目标结构决策优先级：

```text
用户当前明确的新布局 / UX 方案
→ 已确认目标产品设计
→ 必须保留的布局 / 交互 Invariant
→ 目标项目稳定 Layout / Design System
→ Source C3/C2
→ Source C1
→ 推断
```

**C3 证明旧页面真实形态，不等于 Target 必须照抄。**

高风险页面源系统可运行时，不应只依赖源码猜布局；优先检查实际页面、多 Viewport、真实 Scroll / Sticky / Drawer / Modal 行为。

## 11. 前端 Ready Gate

中/高风险复杂前端页面进入大规模开发前，按适用性确认：

```text
功能发现覆盖
+ 来源真实性
+ 源行为覆盖
+ 交互语义覆盖
+ 页面结构覆盖
```

页面结构至少确认：主要区域、父子关系、横纵/Grid/Overlay、关键比例、Scroll Owner、Sticky/Fixed、响应式变化、布局不变量和用户新布局方案。

## 12. 实施与验证

执行链路：

```text
选择功能子项
→ 检查来源真实性
→ 确认迁移决策 / 处理方式
→ 必要时读取 07 / 08
→ 实施
→ 子项即时验证
→ 行为验证
→ 交互验证
→ 结构 / 响应式 / 关键视觉验证
→ 更新状态
```

开发中发现新能力时：**先登记候选 → 判断来源 → 判断范围 → 补契约 → 再决定是否实施**。禁止“顺手新增”。

前端完成不能只检查元素存在；区域顺序、单双栏、宽度比例、滚动、Sticky/Fixed、响应式和关键交互时序错误都应视为验证失败。

差异分类：

```text
行为错误 / 交互错误 / 结构错误 / 视觉错误
已批准行为变化 / 已批准交互变化 / 已批准结构变化
目标原生差异 / 环境噪声 / 未知
```

## 13. 工作流输入基线

中/高风险长任务或多 Agent 工作流冻结：

```text
功能发现 / Source Evidence 版本
源行为版本
用户新 UX / 布局方案版本
目标期望行为版本
迁移决策 / 用户规则版本
目标落点基线
开始时 Git 提交
```

功能发现、用户新方案或目标行为发生实质变化时：`已阻塞 → 更新基线 → 重跑受影响 Gate → 再继续`。

## 14. 并行安全与集成

同一功能子项同时只能有一个生产代码负责人。共享契约 / 公共基础必须唯一负责人。

并行前检查：共享生产文件、Route/Layout/State/Query ownership、API/数据契约、权限/状态机、公共基础、lockfile、registry、generated、全局样式和先后依赖。

如果环境不支持子 Agent / worktree / 隔离工作区，**不得伪造并行能力**，保留工作流模型并串行执行。

以下情况合并后强制集成验证：共享 Route/Layout、API/Query/State、权限、依赖/lockfile、Design System/全局样式、registry/generated、同一发布/切流批次。

## 15. 澄清与用户规则

```text
必须询问 / 可推断 / 可延后
```

只有证据不足且会改变产品行为、权限、数据语义、范围、交互 / 页面目标或不可逆方向时才“必须询问”。目标项目稳定工程惯例优先可推断。

用户规则结构：`作用域 + 触发条件 + 强度 + 动作/约束`。

必须工具不可用时不得静默替代，相关操作标记已阻塞，由用户决定启用、替代、改规则或延后。

## 16. 禁止方式

- 不按文件或目录树一一迁移；
- 不因为代码存在就恢复废弃能力；
- 不只从 UI 单向扫描而忽略反向调用、测试和副作用；
- 不把推断候选、行业惯例或 Agent 建议当成源系统事实；
- 不因为目标项目有组件就自动新增产品功能；
- 不把用户批准的新交互 / 布局方案修回 Source；
- 不把“元素都在”当成页面结构验证通过；
- 不把复杂交互简化成“触发 API”；
- 不让切片已完成掩盖未完成子项；
- 不让验证失败没有明确状态；
- 不把复用目标 / 无需实施伪造成写过代码；
- 不让多个 Agent 并行写同一子项或无法隔离的工作区；
- 不跳过强制集成验证；
- 不静默违反用户规则。

## 17. 结束报告

至少说明：

- 目标与完成能力；
- 功能发现覆盖和来源真实性；
- 功能 / 子项 / 源行为状态；
- 用户新 UX / 布局方案执行情况；
- 交互 / 页面结构 / 响应式验证；
- 迁移决策与处理方式；
- 工作流 / 输入基线 / 集成验证；
- 阻塞 / 延后 / 关键未知；
- 下一动作和 `.code-migration/` 同步状态。
